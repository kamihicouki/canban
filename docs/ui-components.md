# 画面のコンポーネントと呼称

## 作成ダイアログ

アプリバーの「作成」、`c`、⌘Kからレイヤー3の作成ダイアログ（`ui/task-quick-add.*`）を開く。「タスクカード」はタイトル・説明・列・カテゴリを中心にし、その他の所属とラベルは「整理の詳細」にまとめる。「今すぐ始める」はAI App・開く方法・開始設定・実行先・依頼内容を中心にし、セッションカードだけを作る。開始場所はデスクトップアプリと同じ一覧から選ぶ（Claude は「環境」、Codex は「プロジェクト」と「実行場所」）。「フォルダを指定して開始」を明示的に選ぶと作業フォルダを入力でき、保存環境のrefや未適用の設定は持ち越さない。完全適用経路が未確認のClaude環境は理由と元アプリの開始入口を示す。CLI は作業フォルダを使う。Codex の実行場所「クラウド」は Codex Cloud への送信として示す。Desktopは新規画面を開いた結果、CLIはターミナルへ開始を依頼した結果として示し、実行済みとは扱わない。下書きは種類ごとに保持する。`⌘/Ctrl+Enter`で作成・開始、`Esc`と背景クリックでこのダイアログだけを閉じる。

## セッション間のやり取り（0.27.13）

- **やり取りの吹き出し**（`ui/exchanges.*`、レイヤー1）: Codexのカード属性行、休眠カードの1行、時間軸に送信先数／受信元数を表示する。数は取得済みの独立した相手セッション数で、メッセージ数とは分ける。既存のサブエージェントの表示を維持する。
- **関連カードのビュー**（`ui/exchanges-trail.*`、レイヤー2）: 会話内の送受信接点から受信元を左、送信先を右に開く。既存のセッションカードを使う。「横にひろげる／中央に3枚／重ねて辿る」を切り替え、ボードの5配置とは独立した共有UI状態 `exchangeTrailView` に保存する。
- **カードの訪問履歴**: 起点・戻る・進むと、訪問ごとの経路チップ。循環は「再訪」で示す。同一セッションのカード実体は1枚だけ再利用し、下書きとライブ更新の競合を避ける。自動で隣の相手を開かず、操作1回で1訪問だけ増やす。Shift+1/2/3と⌘Kから関連カードのビューを切り替える。Escは上位のポップオーバーや入力離脱を優先し、その後1訪問だけ戻る。
- **やり取りのポップオーバー**（レイヤー4）: カードに420msホバーすると一時表示し、退出後220msで閉じる。ポップオーバーへ移って読め、クリックで固定できる。吹き出し1クリック、選択したCodexカード／開いたセッションのShift+M、⌘K「セッション間のやり取り」から開く。同じ吹き出しで閉じ、Escは最上位だけを閉じる。
- 上部の「時系列／相手別」で同じ履歴を表示する。時系列は新しい順、相手別は最新のやり取り順・相手内は新しい順。各相手を折りたためる。Tabで切替・相手・折りたたみを操作する。見出しと切替は固定し、履歴だけスクロールする。
- 受信元・送信先・本文・時刻と、確認できた起動関係を示す。別セッションをタスクのlinksや親子関係にしない。親／サブ／同じ実行のエージェントは、実際の起動関係だけから区別する。
- 専用の読み取り経路で取得し、既読化・カード移動・指示送信・自動化を実行しない。大きなローカルログは末尾から取得し、一部取得と相手未取得を明示する。リモート・クラウドは履歴未取得を示す。
- [設計・取得範囲](design/session-exchanges.md)。

Canban の画面を作る部品の名前と、それぞれが受け持つことを決める。UI の文言・コード・PR・会話では、ここにある呼称を使う。新しい部品を足すときは、まずこの表に入るかを確かめる。入らないときは、この文書に足してから実装する。

## 原則

- **入口は1か所。** 同じ場所へ行く入口を2つ置かない。サイドバーが唯一の索引になる。
- **開いたものは、同じ入口で閉じる。** 開いている項目をもう一度押すと閉じる。加えて `Esc` で閉じる。
- **バーは1本。** アプリ全体の操作とボードの操作を、1本のアプリバーにまとめる。2段目のツールバーは作らない。
- **空間はサイドバー、時間は時間の帯。** カードを絞り込む操作（どこ・何）はサイドバーに常に出し、有効な条件はアプリバーにチップで示す。期間と寿命（いつ）はボードの上の時間の帯に置く。
- **共通の部品を5種の配置で見る。** 配置と色を選べる。カードの密度は寿命が決め、コンポーネントの見た目は共通。
- **何も選ばなければ、すべて見える。** 絞り込みは押した値だけに絞る。レーンにした軸は絞り込みに出さない。
- **ボードは見えたまま。** 管理パネルはボードを押し出して隣に開き、カード・分析・Agent Usage はボードの上の半透明のオーバーレイに開く。ページ遷移はしない。

## コンポーネント

### 改善ループ（0.27.0）

- **軌道シート**（`view:orbit` / `ui/loop.js`、レイヤー2）: 中心は目標、軌道は1周の段階、半径は確認済みの未達と未知の条件の割合。小さな修正ループは衛星として親の周りに置く。大小2段まで。同じタスクを描き、別ページや全体モードは設けない。
- **ループ部品**（タスク詳細、レイヤー2）: 完了の条件、守る原則、上限、周回の開始、検証根拠、学びと次の調整。履歴は成果物の版・基準の版・根拠を持つ。報告と人による確認を区別する。
- 軌道への索引はサイドバー「見る」の1か所。`Shift+O` と⌘Kも同じ操作。`v` は既存のSlack操作のため使わない。タスクのループ部品へは `Shift+L` と⌘K、部品の横にヒントを付ける。フォームはTab移動・Enterで送信できる。
- 1周回の指示は編集できる下書きを人が送信する。送信要求と周回はSQLiteで一意に結び、二重送信を防ぐ。一時停止は待機中の依頼を取り消す。実行中のCLIは既存の依頼一覧で停止する。
- 軌道は静止させる。基準が変わった箇所と未観測の箇所は線をつながず、周回数だけでは縮めない。親の完了には子の完了と親自身の検証が必要。

## カード内の部品

はい／いいえの回答ボタンは、問いへの「はい。」「いいえ。」を入力欄に入れる。元の問いにない実行・中止の指示は補わず、自動送信しない。ボタン・Alt+1/2・⌘Kで同じ返事を使う。

メッセージのMarkdownプレビュー（`mdHtml()`）は、番号付き手順の最初の番号を `ol start` に保持する。1始まりは通常のリストとし、原文表示は書き換えない。

- 主情報の列と属性の列は、タスク・セッションとも常に2列。既定では会話・説明と入力を左、属性を右に置く。
- パンくず・見出し・状態は、それぞれ独立した可動部品。既定は右列の先頭。部品のつまみは控えめな6点で、ホバーとキーボードフォーカスで強調する。
- 部品はつまみのドラッグまたは矢印キーで列間移動・並べ替え、下端の境界で高さを調整する。列の境界で列幅を変える。
- カードのサイズは右端・下端・右下で調整する。幅と高さ、部品の配置は種類ごとに共有 UI 状態へ保存する。閉じる操作は固定し、部品を移動しても届く。
- カード外の余白はカードボードの受け持ち。キーの案内はカードボードの上に重なる1枚で、余白を空けさせない。
- パンくずのリスト名の横に、左右の隣のリストへ移動するボタンと `Shift+←` / `Shift+→` のヒントを置く。移動後もカードと入力途中の文章を保持する。端のボタンは無効にし、移動先はボードのリスト順に従う。

### セッションのライフサイクル操作

操作セクションから `z` でアーカイブ・復元、`Delete` で永久削除の確認ダイアログ（レイヤー3）を開きます。⌘Kにも同じ操作があります。「隠す」は提供しません。Codex App Serverの `thread/archive`、`thread/unarchive`、`thread/delete` を使用し、エージェントの情報を表示に反映します。Claude・リモートの外部操作APIは未対応で、ボタンを無効にして理由を表示します。実行中・入力待ちの操作も無効にします。

### アカウントの週間ペース

アカウントポップオーバー（レイヤー4）の週間枠は全幅で表示し、使用率のバーと経過時間の目安線を同じ0〜100%の軸で比較します。基準は100%÷7日、差±5ポイント以内は順調、それ以上は使いすぎ、それ以下は余裕あり。判定と差は文字でも表示します。リセット不明・古い値・取得失敗・リセット後は判定保留。5時間枠は独立して表示します。新しい操作・キーは追加しません。

### 出典の共通部品と開始結果

`ui/source-facets.js`はcompact転送の復元と、Codexのプロジェクト／セクション、Claudeの環境／グループ、作業フォルダの共通整形を担う。`p`のピッカーと⌘K（レイヤー4／5）、既存サイドバーの絞り込み・レーン（レイヤー1）、カード3段目と`d`／`f`の右詳細（レイヤー2）に置く。新しいキーや別ページは増やさない。レーンの軸を絞り込みに重複表示せず、複数出典Taskは「複数」レーンへ1回だけ出す。

詳細の「元アプリ」は所属・整理・開始予定／観測・全作業場所・取得状態・取得時刻をまとめる。「なし（確認済み）」「未取得」「古い情報」「取得不能」「取得時刻不明」を分ける。カテゴリとの明示的な対応は既存管理パネルのカテゴリ設定で編集し、他カテゴリの対応を保つ。

Taskの開始も既存`promptComposer()`にAI App、開始設定、マシン／アカウント／作業フォルダを載せる。選択はTaskへ保存し、元アプリから適用を確認できるまでReceiptは未確認と示す。ターミナルのwindow／tab選択は「ターミナルの表示先」。`⌘Enter`、`p`、`d`／`f`、`Esc`、下書きと5配置の共有契約を維持する。


Task開始で結果が未確認の場合、既存composerの説明とtoastに結果を残す。同じpayloadの開始は同じIDの結果確認、依頼文や設定の編集後に開始を押す操作は新しい依頼として扱う。編集だけでは起動しない。開始操作は手動の開始予定を変更しない。

作業フォルダの候補は観測／予定の由来を示し、旧フォルダ名の一意な別名だけ表示上で重複除去する。解決できない旧条件は詳細や旧条件レーンに残す。カテゴリ管理には現在の絞り込みで候補が減ること、Claude環境の対応は開始実績の確認後に有効になることを示す。Taskの状態の隣には「リンクしたセッションの状態」と補足する。

同じ内容を新しく開始する入口は、Task composerの既存⋯メニューと⌘Kの「新しい依頼に切り替える」。未確認の要求があるときに表示し、選択は準備だけ、起動は従来の開始／⌘Enterとする。メニューのTab／Enter操作をキー案内に記載し、新しい予約キーは追加しない。

タスクの開始メニューは既存popoverの上側指定でcomposerの操作の上へ置く。起動失敗のtoastが表示されている直後でも「新しい依頼に切り替える」を読めて押せる位置とし、全体のレイヤーや他popoverの既定配置は変えない。


0.29.28: 作業フォルダの候補は観測した追加場所とTaskの明示的な絶対パス予定の集合を`workingFolder`で検索する。旧`folder`保存条件は別の「旧フォルダ条件」chipとして保持する。保存ビューのカード種別は「タスクカードのみ」／「セッションカードのみ」のchipに示し、同じ場所で解除する。新しい入口や予約キーは足さず、既存のsidebar（レイヤー1）と`p`のピッカー（レイヤー4）と⌘Kのパレット（レイヤー5）を使う。元アプリ4属性と作業フォルダのレーンは、Taskの関連リンクから確認できたなしと未取得を分ける。
### Desktop の接続と開始待機

既存のアカウントポップオーバー（レイヤー4）にClaude Desktopの登録・初回接続・再確認を置く。取消済みの初回接続には対象アカウントを示す「初回接続を再開」を表示し、別アカウントの接続も選べる。候補ごとのログイン状態と下書きを保持する。CLIの接続は別に保持する。作成ダイアログ（レイヤー3）は同一要求の待機・再確認・取消しを表示し、本文と画像を残す。取消しはTab/Enterと⌘K「Desktop の開始待機を取り消す」。Escはダイアログだけを閉じ、待機を取り消さない。実機未確認の切替は無効とする。

リモートDesktopの開始は、作成ダイアログの既存「環境」・「プロジェクト」・「マシン」で選ぶ。アカウント変更時には環境一覧を読み直し、本文・画像を維持する。Codexは準備済み会話をhostId付きで開き、実機未確認時は開始ボタンにその理由を表示する。起動失敗をCLI/Cloudへ置き換えない。

Desktopの添付画像は共通入力欄のサムネイルで保持する。開始時には本文へパス列を追加せず、このMacの画像IDを開始結果に残す。開始結果の「画像をコピー」（Tab/Enter、⌘K「添付画像をコピー」）から明示的にコピーし、アプリで⌘Vを押す。開けたこと・コピーできたこと・画像が実際に添付されたことを区別し、自動送信しない。閉じて再開しても共有下書きのObject URLを保持し、削除・クリア時に解放する。

## カテゴリの固定と全一覧

レイヤー1のカテゴリ一覧は初期に既存順の先頭5件、以降は共有UI状態 `categoryPins` の順で表示する。固定外の選択中カテゴリは末尾に残す。件数0・削除済みIDで固定順を自動変更しない。サイドバー全体の検索時は固定外も対象にする。カテゴリのレーンを使うときは既存どおり絞り込みから外す。

「すべてのカテゴリ…」とAlt+C・⌘Kは同じレイヤー4のポップオーバーを開く。未入力では全カテゴリを表示し、名前と件数を見て選択できる。検索は任意、↑↓・Enterで選択、Tabで別操作の固定ボタン、Alt+Pで現在行を固定・解除、Escで閉じる。固定は所属を変えず共有UIに保存する。選択の再クリックは既存と同じく解除。既存のサイドバー行はカードのドロップ先を維持する。新ページ・密度設定は追加しない。

オムニバーでカテゴリを並べる帯も同じ固定順・選択中の例外・全一覧を使い、固定変更をその場で反映する。Alt+Cは一覧検索入力にフォーカスがあっても再押下で閉じる。旧版の共有UIにcategoryPinsがない場合は現在の固定を消さない。
### Claude Desktop の起動アカウント

共通の起動アカウント欄にDesktopの現在のアカウントを示し、DesktopからCanbanへ戻ると接続状態を読み直す。選択したアカウントが未接続・保持確認待ちなら、起動ボタンへ理由を表示して無効にし、同じ欄の「Desktop の接続・保持確認」へ案内する。カード取得時の旧経路のアカウント警告を重ねない。CLIの実行先・選択中のDesktopアカウント・保存した待機要求は変えない。

- 既存カードの「Claudeで開く」と作成ダイアログで、同じ `desktopAccountPicker()`（レイヤー4）を使う。CLIの実行アカウントとは独立した選択として常時名前を示す。
- 初回接続・保持確認・復元は既存のアカウントポップオーバー内で行う。未接続・確認中・利用可能・再確認が必要を区別する。接続だけでは利用可能にしない。
- `Alt+D` と⌘KでDesktopアカウントを選び、カードの再開待機はカード内で表示・取消しする。待機を閉じても選択と依頼を保持する。作成画面の本文・画像は既存共有下書きへ保持する。

### タスク開始の結果確認と画像（0.29.51）

既存タスクの入力欄（レイヤー2）もDesktop開始後の画像を保持し、「画像をコピー」（Tab→Enter、⌘K「タスク: 添付画像をコピー」）からコピーする。開始メニュー（レイヤー4）と⌘Kの「新しい依頼に切り替える」は、待機の取消し／結果不明の確認を完了してから新しい要求IDへ切り替え、処理中は開始操作を無効にする。Claudeの結果不明を編集だけで別依頼にせず、明示的な確認を案内する。アカウント切替・終了許可の変化だけでは同じ依頼のIDを変更しない。

### マルチエージェントと利用面の横断表示

Codex・Claude Code に加え、Antigravity（IDE / Brain）、Gemini CLI、Cursor（IDE / Agent CLI）、ChatGPT（Desktop）、Grok（CLI / Bot）のセッション・会話履歴・計画進捗を読み取り専用で統合する。対応アプリが増えても操作数や画面の密度を悪化させないよう、既存レイヤーと部品で横断的に扱う。

- **AI App と利用面バッジ**（`faceWho()` / `.who-surf`、レイヤー1・2）: カード3段目・時間軸・スレッド詳細・ライブ HUD で、AI App の色トークンと利用面（`CLI` / `App` / `IDE` / `Cloud`）を一貫した小さなバッジで示す。
- **サイドバー「AI Apps」の動的リスト**（`.side-apps`、レイヤー1）: ボードに実在する（または選択中の）AI App だけを件数・稼働ドット付きで並べ、未使用の AI App は「ほかの AI App（N）…」からレイヤー4のピッカーで選ぶ。

## 統合作業環境の第一段階（0.29.79）

- **時間軸の入れ子**（`ui/inbox.*`、レイヤー1）: タスクの下の会話は閉じて始め、既存の展開ボタンで表示する。選択中の子は閉じた状態でも表示する。選択中の子は折りたたみで隠さない。独立した行には重複表示しない。`j` / `k` は親→子→次の親の順。状態未取得を実行中や要対応へ推定しない。
- **待ちの内容**（`rowWaitLine()`、レイヤー1）: 未回答の質問は原文の先頭120字、計画は確認待ち、実行中は観測した活動を示す。質問の選択肢は最大6件・各40字。回答または新しいターンで古い問いを消す。未回答の入力待ちは既存の24時間の観測範囲まで保持し、実行中だけを15分で待機中へ戻す。
- **質問の読み取り表示**（`paintWaitingQuestion()`、レイヤー2）: 共通入力欄の上に質問と選択肢を出す。元アプリで答える表示だけを置き、承認・回答は実行しない。
- **元アプリへ続ける**（`.thread-continue`、レイヤー2）: セッションのスレッド見出しに主操作を1つ置く。`o`・⌘Kの既存の再開操作と同じ経路・ガードを使う。経路の選択はレイヤー4、Tab / Enter / Escで操作し、閉じると入口へフォーカスを戻す。経路ごとの未確認・非対応・アカウント確認を維持し、開けない理由を示す。無効の既定経路で`o`を押すと理由と経路選択を出し、別経路を自動実行しない。属性パネルには再開設定だけを残す。
- **時間軸のカード**: ドッキング中は選択したカード1枚だけを開く。Enterで大きく開いたタスクは関連セッションを横に置き、Escで選択した1枚へ戻す。既存カードのDOMを再利用して下書きを保持する。

## 仕事の全体像と引継ぎ（2026-11-15）

- **時間軸の仕事一覧**（`lifetime-model.js` / `inbox.*`、レイヤー1）: 仕事を要対応・進行中・次の行動が未記入・そのほかの順に読み、目的（説明の冒頭）・現在地（観測した会話の内訳/最終返答）・次の行動を示す。仕事の状態は所属リスト、会話の応答終了は「応答済み」と区別する。時刻がない返答の時刻は補わない。
- **未整理の会話**: 独立した会話の要対応と実行中は見える位置に残し、そのほかを既存一覧内で畳む。`Alt+U` と⌘Kで開閉。繰り返しの集約は `automation:true` の同題名だけに適用し、元のカードや所属を統合しない。更新中は読んでいる行・選択・下書きを保持する。
- **仕事の引継ぎ**（`task-detail.js` / `thread.js`、レイヤー2）: 既存のタスク本文に現在地・提案された次の行動・担当会話の最終返答・追記報告を置く。`Alt+Shift+H` は既存入力欄の末尾へ引用を追記し、既存文と選択範囲を置換しない。`Alt+Shift+N` は入力文を報告として保存し、エージェントには送らず下書きも保持する。いずれも⌘Kと隣接ヒントを持つ。
- **報告の根拠**: `canban_get_task` は副作用なくタスクと履歴を読む。`canban_append_task_note` は原文とサーバー時刻を追記し、指定の報告元を認証済み作者と扱わない。次の行動は提案であり、人による承認・完了確認と区別する。既存の説明・メモ・会話原本を上書きしない。
- **会話取得の失敗**: 本文だけに再試行を示し、入力欄を作り直さない。権限は「未取得」に遷移し、下書き・選択範囲を保持する。一覧由来の最終返答はその出典と発言時刻未取得を示す。権限のfallback値は観測した権限として表示しない。関連情報がsnapshotまたは未取得なら、その範囲を詳細に明記する。
- **ガントの帯**: 作成から最終更新までの記録の範囲であり、連続して実行した時間ではない。空白期間の活動・進捗・予定を補わない。

- **開いた仕事の更新**: 通常のボード再取得でも、開いている仕事の報告revisionと担当会話を反映する。報告取得中に新revisionが来た場合も後続の取得を取りこぼさず、既存下書き・履歴の開閉・読む位置を保持する。
