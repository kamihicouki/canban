# 画面のコンポーネントと呼称

Canban の画面を作る部品の名前と、それぞれが受け持つことを決める。UI の文言・コード・PR・会話では、ここにある呼称を使う。新しい部品を足すときは、まずこの表に入るかを確かめる。入らないときは、この文書に足してから実装する。

## 原則

- **入口は1か所。** 同じ場所へ行く入口を、1つのレイアウトの中に2つ置かない。ナビゲーション（サイドバー・レール・ドック・タブ）が、そのレイアウトでの唯一の索引になる。
- **開いたものは、同じ入口で閉じる。** 開いている項目をもう一度押すと閉じる。加えて `Esc` で閉じる。
- **バーは1本。** アプリ全体の操作とボードの操作を、1本のアプリバーにまとめる。2段目のツールバーは作らない。
- **絞り込みは見える場所に、見え方の好みは奥に。** カードを絞り込む操作はサイドバーに常に出し、有効な条件はアプリバーにチップで示す。カードの高さ・レイアウト・色は「レイアウトとテーマ」にまとめ、1段深い場所に置く。
- **何も選ばなければ、すべて見える。** 絞り込みは押した値だけに絞る。レーンにした軸は絞り込みに出さない。
- **ボードは見えたまま。** 管理パネルはボードを押し出して隣に開き、カード・分析・Agent Usage はボードの上の半透明のオーバーレイに開く。ページ遷移はしない。

## レイヤー

ボードをレイヤー1とする。収まる中で一番低いレイヤーを使う。`Esc` と背景の押下で閉じるのは、一番上の1枚だけ。

| レイヤー | 名前 | 受け持つもの | 実装 |
|---|---|---|---|
| 1 | ボード面 | アプリバー、ナビゲーション、管理パネル、ボード | `board.html` / `workspace.js` / `layouts.*` |
| 2 | オーバーレイ | カード（セッション1枚、またはタスクと紐付いたセッションの横並び）、分析シート、Agent Usage シート | `card-overlay.*`（`#paneLayer`） |
| 3 | ダイアログ | 確認、タスクの追加 | `<dialog>`、`task-quick-add.*` |
| 4 | ポップオーバー | 表示、ピッカー、リストメニュー、アカウント | `popover()` |
| 5 | パレット | ⌘K コマンドパレット、ショートカット一覧 | `commandPalette()` |

ボード上の1枚は「カード」と呼ぶ。オーバーレイで開いた裏面も、区別が必要なときは「カードの詳細」と呼ぶ。

リストの見出しと最初のカードの間に、リストごとの案内行は置かない。既定リストの「新しいセッションはここに入ります」は、見出しのツールチップとリストの読み上げ用の説明に載せる。

## カード内の部品

- 主情報の列と属性の列は、タスク・セッションとも常に2列。既定では会話・説明と入力を左、属性を右に置く。
- パンくず・見出し・状態は、それぞれ独立した可動部品。既定は右列の先頭。部品のつまみは控えめな6点で、ホバーとキーボードフォーカスで強調する。
- 部品はつまみのドラッグまたは矢印キーで列間移動・並べ替え、下端の境界で高さを調整する。列の境界で列幅を変える。
- カードのサイズは右端・下端・右下で調整する。幅と高さ、部品の配置は種類ごとに共有 UI 状態へ保存する。閉じる操作は固定し、部品を移動しても届く。
- カード外の余白・ショートカットマップはカードボードの受け持ち。カード内の配置変更では変更しない。
- パンくずのリスト名の横に、左右の隣のリストへ移動するボタンと `Shift+←` / `Shift+→` のヒントを置く。移動後もカードと入力途中の文章を保持する。端のボタンは無効にし、移動先はボードのリスト順に従う。

部品は5種で共通。並べ方だけを `body[data-layout]` で変える。どのレイアウトでも、管理パネルはナビゲーションの隣に開き、カード・シートはオーバーレイに開く。

| レイアウト | ナビゲーション | アプリバー | 管理パネルの位置 | 固有の部品 |
|---|---|---|---|---|
| Trello（既定） | サイドバー（ビュー・レーン・絞り込み、下端に見る・管理・レイアウトとテーマ） | 全幅 | サイドバーの右 | — |
| 定番 | サイドバー（上まで通り、ロゴを持つ） | サイドバーの右 | サイドバーの右 | — |
| レール | レール（すべての場所とレイアウトとテーマ）。隣の列はビュー・レーン・絞り込み | レールとサイドバーの右 | サイドバーの列（開いている間は差し替える） | レール |
| オムニバー | ドック（すべての場所とレイアウトとテーマ） | 全幅。検索、カテゴリの帯、絞り込みボタンを置く | 左端 | ドック、カテゴリの帯、絞り込みボタン |
| ライブ HUD | タブ（ボード・分析・Agent Usage）とサイドバー（ビュー・レーン・絞り込み、下端に管理・レイアウトとテーマ） | 全幅。タブを置く | サイドバーの右 | タブ、ライブ HUD |

### セッションのライフサイクル操作

操作セクションから `z` でアーカイブ・復元、`Delete` で永久削除の確認ダイアログ（レイヤー3）を開きます。⌘Kにも同じ操作があります。「隠す」は提供しません。Codex App Serverの `thread/archive`、`thread/unarchive`、`thread/delete` を使用し、エージェントの情報を表示に反映します。Claude・リモートの外部操作APIは未対応で、ボタンを無効にして理由を表示します。実行中・入力待ちの操作も無効にします。

### アカウントの週間ペース

アカウントポップオーバー（レイヤー4）の週間枠は全幅で表示し、使用率のバーと経過時間の目安線を同じ0〜100%の軸で比較します。基準は100%÷7日、差±5ポイント以内は順調、それ以上は使いすぎ、それ以下は余裕あり。判定と差は文字でも表示します。リセット不明・古い値・取得失敗・リセット後は判定保留。5時間枠は独立して表示します。新しい操作・キーは追加しません。

## Slack操作（0.24.0）

タイムラインはレイヤー1。Trello・定番・ライブHUDではサイドバーの絞り込みから表示し、レール・オムニバーではそれぞれレール・ドックのSlackから表示する。`v` と⌘Kでも表示を切り替え、列内の閉じるボタン・`Esc`でタイムラインだけを隠す。管理の「Slack接続」は各レイアウトの管理ナビゲーション1か所から開く。

メッセージ上で `c` は編集できるタスク追加ダイアログ（レイヤー3）、`l` はカードピッカー（レイヤー4）、`t` は列内の返信の開閉。⌘Kにも選択したメッセージの操作を出す。カードのSlack資料はレイヤー2で、`Alt+s`で資料の追加ボタンへ移動し、`Enter`で確認した本文を依頼文へ追加する。フォームの保存・取得・解除・履歴開閉はTabで移動してEnter/Spaceで操作できる。⌘Kはレイヤー5。

## コンポーネントのスタイル（0.25.0）

同じ役割に2つ以上の見た目があるコンポーネントは、ユーザーが1つずつ選ぶ（「レイアウトとテーマ」→ コンポーネントのスタイル、または ⌘K の「スタイル: …」）。値は共有 UI 状態の `componentStyles` に保存し、`body[data-cs-<名前>]` で CSS に伝える。

| コンポーネント | 選択肢（既定は太字） | 実装 |
|---|---|---|
| ボードのカード `boardCard` | 現行 / コンパクト / **標準** / リッチ | `renderCard()` → `renderFaceCard()`（`card-face.*`） |
| カードのその場返信 `peek` | **使う** / 使わない | `withPeek()` / `togglePeek()`（`card-face.js`） |
| ボードの表示 `boardView` | **ボード** / 受信トレイ | `renderInbox()`（`inbox.*`） |
| カード詳細 `detail` | **スレッド** / モジュール | `renderThreadPane()`（`thread.*`）/ `renderPane()` のモジュール |
| 会話の表示 `conversation` | **折りたたみ** / 現行 | `feedPush()` / `editSummary()`（`thread.js`） |
| 入力欄 `composer` | **チップ** / 現行 | `renderDispatch()`、`promptComposer({ chips })` |
| タスクカード詳細 `taskDetail` | **スレッド** / 現行 | `openTaskCard()`、`threadStrip()` |
| 変更のレビュー `review` | **使う** / 使わない | `renderChangesPanel()`、`canban_get_changes` |
