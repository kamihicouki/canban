# ワークスペース（2列）表示の設計（Fable 5.2、2026-11-15）

対象: origin/main `d057b3f`（0.29.86）。実装とレビューは Codex。コードは変更していない。

ユーザーの依頼:

1. ツールバー／トップバーの高さを小さく。
2. カードのヘッダー要素を無くし、2カラムを主にする。今のヘッダ付きカード型は切り替えられる表示として残す。
3. タスク／セッションの会話領域を大きく、動的に。起点の冒頭プロンプト・関連・現在地（末尾メッセージ）へ少ない操作で届く。

今回のユーザー指示は元の UI 規約より優先する（新しい表示の切り替えは明示の許可あり）。

## 結論

**推薦は案A「文脈＋会話」。** カードの中を、左に文脈（目的・起点・関連・観測した現在地）、右に会話と入力、の2列にする。今のヘッダー2段は無くし、中身を左の列へ移す。

案B「一覧＋会話」は、時間軸とガントのドックとしてすでにある。捨てずに、同じカードをドックしたときの形として両立させる。ドック中は左の文脈列を畳み、一覧＋会話の2列になる。**どの場面でも固定の列は2つまで。**

実装は「形」と「置き方」を分ける。形（ワークスペース／カード型）を新しく足し、置き方（全画面・スプリット・シート・ドック）は今のまま使う。本文のレンダラ、入力欄、権限の表示、下書きと読む位置の保存は触らない。

サーバー側に1つだけ追加が要る。**会話は末尾しか読み込んでいない**ので、今のままでは「冒頭へ」が原文の位置へ飛べない（後述）。

## 2案の比較

| | 案A 文脈＋会話 | 案B 一覧＋会話 |
|---|---|---|
| 左の列 | このカードの目的・起点・関連・観測した現在地 | ほかのカードの一覧 |
| ヘッダーを無くせるか | 無くせる。中身の行き先が左の列 | 無くせない。題名・状態・道具の置き場が要る |
| 起点・関連・現在地へ | 左の列に常に出ている。1手 | 今と同じ。詳細パネルかスクロール |
| 会話の高さ | ヘッダーのぶん約75px増える | 変わらない |
| 会話の幅 | 変わらない（空白を使う） | 一覧のぶん減る |
| 別のカードへ移る | `j`/`k`、関連の行、`Esc` | 一覧から1手 |
| 新しく作る量 | 左の列の組み立て（既存の部品の並べ替え） | ほぼ無い（既にある） |
| Codex / Antigravity との近さ | 遠い（あちらは一覧＋会話） | 近い |

ユーザーの言葉は「ヘッダーを無くす」「起点・関連・現在地へ少ない操作で」。この2つを満たすのは案A。案Bは形は参考アプリに近いが、依頼の中身を満たさない。

一方、仕事を選ぶ場面では一覧が要る。そこで次のように分ける。

- **ボードから開く**: 文脈＋会話（案A）。
- **時間軸／ガントで選ぶ**: 一覧＋会話（案B）。同じカードがドックされ、文脈の列は畳んだ状態で始まる。キー1つで文脈を開ける。

## 設計

### 1. 形と置き方を分ける

今は `CARD_VIEW_MODES = full / split / sheet` が1つの軸で、ドック中は `data-view-mode="docked"` に上書きされる（`ui/card-overlay.js:95`）。ここに「ワークスペース」を足すと、ドック中に形を選べなくなる。

- 新しい設定 `paneGlobal.shape`: `workspace`（標準）／`card`（今のヘッダ付き）。
- `paneLayer.dataset.shape` に出す。`data-view-mode` は今のまま。
- 既存の利用者も `workspace` で始める。初回だけ「表示をワークスペースに変えました。`w` でカード型に戻せます」と知らせる。`full` は選んだ値ではなく初期値なので、引き継ぐ理由がない。
- 切り替えの入口: カード上のバー（`.pane-bar`）の「表示モード」の隣に2択を1つ。⌘K にも「カード型で表示／ワークスペースで表示」。

### 2. ワークスペースのカードの中

```
┌ 文脈（約300px）─────┬ 会話 ──────────────────────────┐
│ 題名（2行まで）      │                                │
│ 状態・エージェント    │   既存の .feed（そのまま）      │
│ リスト ▾ ／ 親タスク  │                                │
│ 属性の小片           │                                │
│ ─ 起点 ──────── s   │                                │
│ 最初の依頼の先頭3行   │                                │
│ ─ 関連 ──────── n   │                                │
│ 親タスク／同じ仕事の  │                                │
│ 会話／関連カード／PR  │                                │
│ ─ 現在地（観測）─ e  ├────────────────────────────────┤
│ 最後の発言の主・時刻  │   質問の行（あるとき）          │
│ 先頭2行／観測の時刻   │   既存の入力欄（そのまま）       │
│ ─────────────────   │                                │
│ o 開く  y f t d  ×   │                                │
└─────────────────────┴────────────────────────────────┘
```

- `.th-head` と `.th-meta` は出さない。中の要素（`secs.title`、`secs.breadcrumb`、`secs.status`、`secs.continue`、小片、道具のボタン）は**作り直さず、同じノードを左の列へ移す**。0.29.86 の `compactThreadHeading` と同じやり方。ボタンのキーと動きは変わらない。
- 左の列の幅は `clamp(260px, 22cqi, 340px)`。右の列は残り全部。本文の上限 54rem は今のまま、右の列の中で中央に置く。
- 左の列は自分でスクロールする。会話のスクロールとは独立。
- 「思考・実行ステップ」（`y`、`.th-timeline`）は、左の列を切り替えて出す（文脈 ⇄ ステップ）。左に2列並べない。
- 詳細・変更・ターミナル（`d` `f` `t`、`.th-side`）は今のまま右から出る。開いているあいだは3列になるが、これは一時の重ね置きで、今と同じ。
- カード上のバー（`.pane-bar`）は、ワークスペースでは高さを取らない。会話の表示（テキスト／プレビュー／要点）と表示モードは左の列の一番下へ移す。

#### 左の列の中身と出どころ

| 区画 | 出すもの | 出どころ | 取れないとき |
|---|---|---|---|
| 見出し | 題名、状態、エージェント、リスト、親タスク、属性の小片 | 既存のノードを移す | 今と同じ |
| 起点 | 最初の依頼の先頭3行、時刻 | 会話が先頭まで読めていれば最初の `.fi-user`。読めていなければ `s.preview` | 「最初の依頼は未取得」 |
| 関連 | 親タスク、同じ仕事の会話、関連カード、PR、ブランチ | `secs.task` `secs.cardRelations` `secs.related` `secs.pr` | 区画ごと出さない |
| 現在地（観測） | 最後の発言の主・時刻・先頭2行、状態、質問があればその先頭 | 読み込み済みの会話の最後の `user`／`assistant`、`paintWaitingQuestion` | 「会話は未取得」 |

- 見出しは「現在地（観測）」とし、観測した時刻を添える（「3分前に取得」）。**進捗、完了率、次の担当といった、観測していないものは書かない。**
- タスクのカードでは、起点＝説明の先頭3行（無ければ「目的は未記入」）、関連＝紐付いた会話の行（状態、最後の発言の先頭、観測の時刻、`fresh/stale/unavailable` をそのまま語にする）、現在地＝次の行動の提案と出どころ・最新の報告の先頭。0.29.85 の `linkedSessionContext` をそのまま使う。

### 3. 起点・関連・現在地へ飛ぶ

飛び先は原文の位置。要約や別の画面へは行かない。

| 操作 | 動き |
|---|---|
| 起点（`s`、区画をクリック） | 会話の最初の `.fi-user` へ `scrollIntoView({block:'start'})`。その発言に1.5秒の枠 |
| 現在地（`e`、区画をクリック） | 既存の `scrollFeedToEnd(feed)` |
| 関連（`n`） | 関連の区画の最初の行にフォーカス。`↑↓` で行を選び、`Enter` で今と同じ開き方 |
| 発言へ（ステップの行） | 今の `scrollIntoView`（変更なし） |

**先頭が読み込まれていない会話の扱い（要サーバー変更）。** 今の取得は末尾だけなので、長い会話では最初の `.fi-user` は起点ではない。そこへ飛んで「起点」と呼ぶと誤りになる。

- 取得結果に「先頭から読めているか」を1つ足す（`feed.fromStart`。読み始めの位置が0で、120件の上限で切っていないとき `true`）。
- `fromStart` が `true`: 上の表のとおり飛ぶ。
- `false`: 起点の区画に「会話の先頭は未読み込み（末尾◯件を表示中）」と出す。`s` を押すと先頭の部分を取得して、今のレンダラ（`feedPush`）で会話の上に足す。先頭と末尾のあいだには「この間の発言は読み込んでいません」という行を1つ置く。そこから飛ぶ。
- 先頭の取得ができない／失敗した: `s.preview` を区画に出したまま、「原文の位置へは移動できません。元アプリで開く」と出す。飛んだふりをしない。
- 先頭を足しても、読む位置と下書きは動かさない（足す前の `scrollHeight` との差で補正する）。

この1点は見た目ではなくデータの変更で、MCP のツールは増やさない（画面用の取得だけ）。

### 4. タスクと会話の行き来

今はタスクを開くと、紐付いた会話のカードが横に並ぶ（`.pane-row`）。ワークスペースでは、右の列に出すのは1枚だけにする。

- 開いているカード（`panes`）は今のまま全部持つ。**見せるのを1枚にするだけ**（ほかは `hidden`）。カードを作り直さないので、下書き・キャレット・読む位置・権限の状態はそのまま残る。
- 切り替えは既存の `[` / `]`（`stepPane`）と、関連の行の `Enter`。会話からは `Esc` でタスクへ戻る。
- 会話のカードの関連には、親タスクと、同じ仕事のほかの会話が並ぶ。これが「仕事 → 会話 → 仕事」の往復になる。
- カード型（`shape=card`）では今の横並びのまま。

### 5. ドック（時間軸・ガント）と狭い幅

- ドック中は、文脈の列を畳んで始める。一覧＋会話の2列。
- 畳んだとき、カードの上に1行（約32px）だけ残す: 題名（1行で省略）、状態、`起点 s`、`現在地 e`、`文脈 q`。これが無いと何を読んでいるか分からなくなる。**ヘッダーが完全に0になるのは、文脈の列が開いているときだけ。**
- `q` で文脈の列を開く。ドック中と幅960px未満では、会話に重ねて出す（今の `.th-side` の狭いときと同じ出し方、`@container`）。幅960px以上の全画面では並べて出す。
- 開閉は、ドック中／ドック外で別々に覚える。
- ワークスペースのサイドバー（`b`）は今のまま。自動では閉じない。

### 6. 会話の領域を動的に

- 入力欄: フォーカスが無く下書きが空のとき、入力1行＋道具の行だけにし、キーの行（`.cx-keys`）は出さない。フォーカスで今の形に戻る。下書きがあるときは畳まない。
- 権限の小片、確認の帯、送信の条件は変えない。
- 入力欄が伸び縮みしても、末尾を追っているときは末尾に留まる（既存の `cardSizeObserver` の動き）。追っていないときは読む位置を保つ。
- 質問の行（`paintWaitingQuestion`）は今のまま。

### 7. トップバー

- 高さ 52px → 40px。ボタン 32px → 28px、ロゴ 28px → 22px、検索欄も同じ高さへ。文字の大きさは変えない。
- 中身と並びは変えない。隠すものも足すものもない。
- 押せる範囲は28px以上を保つ。キーで届く操作は今と同じ。
- カードを全画面で開いているあいだだけトップバーを隠す、という案は採らない。検索・作成・表示の切り替えに届かなくなる。

## キーと衝突

カードの中で使われているキー（`ui/card-overlay.js:396-425`）: `?` `r` `a` `u` `j` `k` `[` `]` `v` `1`〜`3` `i` `y` `d` `f` `t` `z` `Delete` `x` `o` `l` `g` `m` `h`、`Shift+R` `Shift+X` `Shift+←→` `Enter`（ドック中）、`Shift+1〜3` `Shift+Home`（やり取りの軌跡があるとき）。

全体（読めた範囲、`ui/keyboard.js`）: `/` `?` `b` `[` `]` `r` `a` `u` `c` `v` `p` `i`、`Shift+V` `Shift+O` `Shift+L`、`Alt+…` 各種。

| 新しい操作 | 提案 | 衝突 |
|---|---|---|
| 形の切り替え（ワークスペース ⇄ カード型） | `w` | 読めた範囲では空き |
| 起点へ | `s` | 空き |
| 現在地（末尾）へ | `e` | 空き |
| 関連へ | `n` | 空き |
| 文脈の列の開閉 | `q` | 空き |

- `g` は使えない（カテゴリの選択に割り当て済み）。`gg` / `G` は採らない。
- `Home` / `End` は採らない。ボードのリスト内の移動、サイズ変更のつまみ、キーの案内、時間の帯で使われており、フォーカスの場所で意味が変わる。`Shift+Home` は「やり取りの起点へ」で、言葉も近く紛らわしい。
- **言葉の衝突**: 既存の「やり取りの起点へ戻る」（`Shift+Home`、カードをたどった最初のカード）と、今回の「起点」（会話の最初の依頼）は別物。今回のほうは画面の語を「最初の依頼」にし、キーの案内では「最初の依頼へ」と書く。
- `v` はもともと二重（全体では Slack の表示、カードの中では表示モード）。今回は触らないが、`w` を足すときに同じ二重を作らない。
- ドック中、フォーカスが一覧の行にあるときはカードのキーが届かない（`ui/card-overlay.js:397`）。`s` `e` `n` `q` を、行のキー表（`ui/inbox.js:33-41`、`ui/gantt.js:50` 付近）にも足す。今の `d` `f` と同じやり方。
- 文字入力中（入力欄、IME の変換中）は、どれも働かない。今の判定のまま。
- キーの案内（`key-guide.js`）と `?` の一覧に5つを足す。
- Codex が確かめること: `ui/keyboard.js:342` 付近の全体のキー表、分析・軌道などシートの中、ターミナルにフォーカスがあるとき、の3か所で `w` `s` `e` `n` `q` が空いているか。

## 受入

登録 Chrome、実データ、ユーザーの窓の大きさと 1280×800、ライト／ダーク。架空データの結果は別に記す。

形と切り替え

- カードを開くと、ヘッダーの段が無く、左に文脈、右に会話と入力がある。固定の列は2つ。
- `w` でカード型（0.29.86 と同じ見た目）になり、もう一度で戻る。選んだ形は再読み込み後も同じ。
- 切り替えの前後で、下書き・キャレット・読む位置・開いている詳細パネル・権限の小片の内容が変わらない。
- トップバーが40pxで、すべてのボタンが押せ、キーで届く。

会話の大きさ

- 添付と同じ会話・同じ窓で、会話の高さが100px以上増えている。本文の1行の長さは変わっていない。
- 入力欄にフォーカスすると今の形になり、外すと畳まれる。下書きがあるときは畳まれない。
- 権限が「制限なし」の会話で、確認の帯と送信の条件が 0.29.86 と同じ。

起点・関連・現在地

- 短い会話（先頭まで読めている）で `s` を押すと、最初の依頼の発言が見える位置に来る。`e` で末尾に来る。それぞれ1手。
- 長い会話（先頭が読めていない）で、起点の区画に「未読み込み」と出ている。`s` で先頭が足され、あいだに「読み込んでいません」の行が出る。飛んだ先の文が、元アプリの最初の依頼と一致する（人が見比べる）。
- 先頭の取得を失敗させたとき、飛ばず、理由と「元アプリで開く」が出る。
- 現在地の区画の発言の主・時刻・文が、会話の末尾の発言と一致する。観測の時刻が出ている。会話を取得できていないカードでは「未取得」と出て、文が入っていない。
- 画面のどこにも、観測していない進捗・完了・担当の語が出ていない。
- `n` → `↓` → `Enter` で親タスクへ移り、`Esc` で元の会話に戻る。戻ったとき下書きと読む位置が同じ。

タスク

- タスクを開くと、右は1枚だけ。`]` で紐付いた会話、`[` でタスクに戻る。往復して、両方の下書きが残っている。
- 紐付いた会話の行に、状態・最後の発言の先頭・観測の時刻が出る。取れていない会話は「未取得」。

ドックと狭い幅

- 時間軸でカードを選ぶと、一覧＋会話の2列で、カードの上は1行だけ。`q` で文脈が会話に重なって出て、もう一度で消える。
- フォーカスが一覧の行にあるまま、`s` `e` が働く。
- カード幅700pxで、文脈が並ばずに重ねて出る。

変えていないこと

- 既存のキーがすべて今のまま働く。
- 本文の描画（Markdown、道具の行、質問）が 0.29.86 と同じ。
