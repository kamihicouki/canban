# 統合作業環境 第一段階（U1・U2）の実装後評価

2026-11-14。対象は PR #93（0.29.78、`codex/unified-workspace-design-20261114`）。[implementation-report.md](implementation-report.md) を読み、Codex が立てた隔離サーバー `http://localhost:4632/direct` を Claude Desktop のアプリ内ブラウザで操作した。評価者のモデルは、このセッションの自己申告で Fable 5.2（`claude-fable-5-2`）。

## 結論

U1 と U2 の骨格は意図どおりに動いた。質問の中身を元アプリへ行かずに読め、続ける操作が見出しにあり、時間軸の右は選んだカード1枚に収まり、下書きと読む位置は 親→子→拡大→ドッキング の往復で保たれた。

マージ前に直すことを勧めるのは3点。

1. **経路の選択ボタン（▾）が「思考」ボタンの下に隠れて押せない。**（不具合 B1）
2. **主操作が無効のとき、使える経路があっても主ボタンは死んだままで、`o` は何も言わない。**（不具合 B2）
3. **入力待ちが15分で「待機中」に変わり、質問が画面から消える。**（既存の挙動だが、U1 の価値を直接削る。B3）

## 評価の条件

- 1280×800。ライトで全経路、ダークで 子の選択→質問→経路の一覧→拡大→ドッキング。狭幅は 1000×800 と 820×800（ライト）。
- 架空データ: タスク「決済フォームの検証」＋ Codex「ログイン修正」＋ Claude「README 修正」（未回答の質問、220メッセージ）。
- 証跡は [evidence/review/](evidence/review/)。取得ツールの都合で 800×500 前後に縮小されている。寸法の数値はページ内で実測した値。
- **行っていないこと**: 外部アプリの起動、実会話への送信、承認、サーバーの停止、製品コードの変更、コミット。有効な「Codex で開く」と経路の一覧の各項目は押していない。
- **行ったこと（開示）**: 評価の途中で架空の transcript（一時フォルダーの `claude/projects/-r-web/c2.jsonl`）の更新時刻を `touch` で現在に直した。作成から15分が過ぎて入力待ちが「待機中」へ変わり、質問を観測できなくなったため（B3）。中身は変えていない。無効の主ボタンに対して `o` を1回押した（何も起きないことの確認。サーバーは `CANBAN_LAUNCH_DRYRUN=1`）。

## 不具合

### B1 経路の選択（▾）が「思考」ボタンに覆われて押せない（要修正）

- 再現: 時間軸で Claude のセッションを選ぶ。1280（ドッキング）・1248（拡大）・1000・820 のすべてで同じ。
- 実測（1280、ドッキング）: `.thread-continue` は x 650–846。`.continue-options` は 848–876。「思考」は 850–935。▾ の中心の最前面要素は「思考」ボタン。
- 原因の見立て（ソース `ui/thread.css` 158–163行）: `.resume-main` が `max-width: 100%` で親の幅を使い切り、`flex: none` の ▾ が親の外へ押し出される。親 `.thread-continue` は `flex: none` なので、はみ出した分が次の兄弟（思考）と重なる。主ボタンを `flex: 1 1 auto; min-width: 0` にして ▾ を親の内側へ収めるのが素直。
- 影響: マウスでは経路を選べない。B2 と合わさると、Desktop が未接続の人は「ターミナルで再開」へポインターで辿り着けない。

### B2 主操作が無効のとき、使える経路へ進めず、`o` が無言（要修正）

- 再現: Claude「README 修正」。主ボタンは「Claude で答える」無効、理由「Desktop の接続を確認してください」。経路の一覧を開くと「ターミナルで再開」「新規ウィンドウ」「新規タブ」「既存ウィンドウ」は使える。
- `o` を押しても何も起きず、トーストも出ない。
- 設計の意図（design.md §6.2）は「続けられるなら続ける、できないなら理由」。使える経路があるのに主操作が止まっているのは、理由の表示としては正しくても、続ける体験としては止まっている。
- 提案: 既定の経路が `blocked`／`unknown` で、ほかに `available` の経路があるとき、主ボタンはその経路にする（「ターミナルで答える」／「ターミナルで再開」）。Desktop が使えない理由は補足の行に残す。使える経路が1つもないときだけ無効にする。無効のまま `o` を押したら、理由を既存のトーストで出す。経路ごとのガードは今のまま通す。

### B3 入力待ちが15分で「待機中」になり、質問が消える（既存。U1 の前提として要対応）

- 観測: 評価開始時（transcript の更新から14分）は 要対応・入力待ち・「質問: …」。15分を過ぎると区分は「今日」、状態は「待機中」、行の2行目も入力欄の上の質問も消えた。更新時刻を現在に直すと元に戻った。
- 原因（ソース `server/status.mjs` 16–23行）: `settle()` が `running` と `waiting` の両方を、15分書き込みがなければ `idle` にする。実行中の取りこぼし対策としては妥当だが、質問は人が答えるまで書き込みが起きないのが普通。
- 影響: 席を外して20分後に戻ると、答えを待っている質問が要対応から消えている。U1 が解いたはずの「待ちの中身を読める」が、いちばん必要な場面で成り立たない。
- 提案: 未回答の問い（`asks` が残っている）による `waiting` は時間で `idle` に落とさない。上限を置くなら既存の `RECENT_MS`（24時間）に合わせ、それを過ぎたら「状態は未取得」か、質問の時刻を添えた表示にする。実機の Desktop で、質問を放置した会話の transcript が本当に更新されないかは未確認なので、Codex 側で確かめてほしい。
- PR #93 の差分が入れた挙動ではない。直すなら別の単位でもよいが、U1 の受け入れ条件「質問待ちの行に質問が出る」は15分以内に限って成り立つ、と PR に書くべき。

### B4 一覧と右のカードで状態が食い違う時間がある（軽微）

- 観測: 右のカードは「入力待ち」と質問を出しているのに、左の一覧は「今日」・質問なしのまま。`r` を押しても変わらず、その後の再描画（表示幅の変更）で揃った。待った時間は数十秒。
- 原因の見立て: カードが開いている間の `r` は開いているカードだけを読み直す（`ui/keyboard.js` の「再読み込み」）。時間軸では右のカードが常に開いているので、`r` で一覧を読み直せない。
- 提案: 時間軸でドッキング中の `r` は一覧も読み直す。既存の挙動なので、この PR の必須ではない。

### B5 `r` のあと、フォーカスが入力欄へ移る（軽微）

- 観測: 子の行にフォーカスがある状態で `r`。読み直しのあと、フォーカスは入力欄の textarea にあった。続けて `j`／`k` を打つと文字として入る。
- 入力欄で `Esc` を押すとフォーカスは body へ抜け、行には戻らない。body からでも `j`／`k` は効くが、`Enter` は効かない（行にフォーカスがないため拡大しない）。キーの案内は「カード選択」に変わるので、拡大できない理由が画面から分からない。
- 提案: 読み直しで行のフォーカスを奪わない。入力欄の `Esc` は選択中の行へフォーカスを戻す。

## 改善点

- **I1 待ちの表示が二重**: 会話の末尾の「❓質問への回答待ち AskUserQuestion（アプリで答えてください）」と、その直下の質問の箱が同じことを2度言う。ツール名 `AskUserQuestion` は人向けの言葉ではない。質問の箱があるときは上の行を出さないか、箱の見出しへまとめる。
- **I2 無効の主ボタンが薄すぎる**: 不透明度 0.45 で、ライトでもダークでも「Claude で答える」が読みにくい。どこへ続けるのかはこのボタンの文字が一番の手がかりなので、無効でも文字は読める濃さにする（色だけで無効を伝えず、理由の行は今のまま残す）。B2 を直せば無効になる場面自体が減る。
- **I3 質問があるときの会話の高さ**: 1280×800 のドッキングで会話は 195px。見出し75＋題名と属性＋待ちの行＋質問の箱112＋入力欄＋キーの行が積まれる。1000px で 174px、820px で 146px。「思考・実行ステップ」の列（幅約160px、会話の全発言を複製）が開いたままだと横も狭い。I1 の統合で1行分は戻る。思考の列を既定で閉じるかは、長会話の扱い（design.md §2.2-6）と一緒に後続で決めたい。
- **I4 理由の文言が揺れる**: 同じカードで「Desktop の接続を確認してください」と「未接続です。Desktop の初回接続へ進んでください」が、ドッキングと拡大・時間の経過で入れ替わった。接続状態の読み込み前後の差と思われる。後者のほうが次の行動が分かるので、確定するまでは「確認中」と出すと揺れに見えない。
- **I5 理由の行が小さい**: 11px。ダークの色は読めるが、無効の主操作の唯一の説明としては小さい。12px 以上を勧める。
- **I6 Codex の行の時刻**: 「ログイン修正」は `2026/9/21` と絶対日付で、同じ一覧のほかの行は相対表記。架空データが古いだけなら問題ないが、30日の期間内に入っている理由（タスクの子だから）が画面からは読めない。
- **I7 `i` の切り替え**: キーは ボード⇄時間軸 の2方向、ボタンは ボード・時間軸・ガント の3つ。ガントはボタンからだけ入れる。U5 でキーの説明と揃える。

## 設計・仕様どおりだった点

- 質問の箱に回答・承認の部品がない。答えは元アプリで行う。
- 主ボタンは見出しに1つ。詳細パネルには設定だけが残る。
- 文言が経路と状況を言い切る（入力待ちは「Claude で答える」、応答済みの Codex は「Codex で開く」）。
- 無効のときは色だけでなく理由の文がある。
- 新しいキーなし。既存の `j`／`k`・`Enter`・`Esc`・`d`・`o` で通る。
- 狭幅で主ボタンの文字を畳み、`aria-label` に全文が残る。
- 既定の表示はボードのまま。

## Q1（入口を時間軸にするか）

引き続き保留でよい。B1〜B3 が直り、U3（まとめる）と U4（探し直す）が入ってから、もう一度同じ経路を歩いて判断材料を出す。
