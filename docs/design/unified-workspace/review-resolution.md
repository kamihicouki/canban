# 実装後評価への対応

Claude DesktopのFable 5.2による[体験評価](implementation-review.md)を受けて、Codexで以下を対応する。評価原文は変更しない。

| 指摘 | 対応 |
|---|---|
| B1 経路選択が隣のボタンに覆われる | 主ボタンを縮小できるflex項目にし、経路選択を同じ枠内に収める。DOMのclickだけでなくelementFromPointでマウス到達性を検証する。理由は12pxへ広げる |
| B2 無効のoが無言・別経路が使える | oでも既存toastへ無効理由を示す。経路選択はB1で操作可能にする。Desktopのunknown/blockedを理由にCLIへ自動切替する提案は採用しない。利用者が選んだ実行経路・アカウント・許可境界を維持し、別経路は一覧から明示的に選ぶ |
| B3 質問が15分で消える | 未回答のwaitingは既存24時間の観測範囲まで維持する。runningは従来どおり15分でidle。回答・新ターンで待ちを消し、古い待ちを無期限に保持しない |
| B4 一覧とカードの再取得範囲 | 既存の再読み込みの範囲として後続。B3による15分境界の非同期な状態変化は今回修正する |
| B5 rで入力欄へ移る | 時間軸の行にフォーカスがあるrは既存コードで入力欄へ移る操作として実装されている。グローバルの再読み込みと文脈が異なる。読む位置・選択は保持し、文脈に応じたヒントの明確化は後続候補 |

I1の待ち表示重複、I3の会話の高さ、I4の接続読込前後の説明、I6の期間外の子の由来、I7のガントとiの契約は後続候補。I5の理由の文字サイズはB1の修正で12pxにする。元アプリへの実際の起動・実会話送信・承認・登録拡張への反映は引き続き未検証。

## 再確認の結果と送信前ガードへの波及

Fableは[再確認](implementation-review-followup.md)でB1/B2を実画面（1280×800ライト・ダーク、820幅）から解消と評価し、B3はコードと15件の関連試験で確認した。15分を越えた実画面・元アプリの実会話での確認とは区別する。

B3の`settle()`は送信前にも使われる。`timingProblem()`は未回答の待ちを「アプリかターミナルで答えてください」として返すため、即時送信は拒否され、キュー処理は`session_busy`でblockedにして一時停止する。20分放置した質問でもこの既存ガードを維持することが意図した動作で、質問へ追加依頼を割り込ませない。回答・新ターンで待ちが消えること、既存24時間上限の後は古い待ちを残さないことを、架空レコードの`timingProblem()`回帰試験でCodex・Claudeの両方について確認した。送信を実行する試験ではない。
