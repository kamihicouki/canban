# 完成計画への設計確認

2026-11-14、Claude Desktop の Fable 5.2（`claude-fable-5-2`）。対象は [完成計画](../../superpowers/plans/2026-11-14-unified-workspace-complete.md) と、ブランチ `codex/unified-workspace-complete-20261114` の未コミットの作業ツリー（基点 `f87e3db`）。

コードを読んだだけで、画面は操作していない。ここに書く挙動はコードからの読み取りで、実画面での確認は隔離プレビューを受け取ってから行う。製品コードは変更していない。

## 結論

計画の方向は新しい指示に合っている。U3・U4・U5 の実装も設計の範囲に収まっている。ただし「最小」の解釈が指示とずれている箇所があり、そのままだと会話は広がる代わりに、状態が見えなくなる。重要な修正は次の6点。

| # | 修正 | 重さ |
|---|---|---|
| 1 | 最小を「非表示」にしない。状態を示す小片を残す | 必須 |
| 2 | 一括トグルが個別の開閉を上書きしないようにする | 必須 |
| 3 | 「仕事にまとめる」で `x` → `Enter` が紐付け解除になる | 必須 |
| 4 | `i` の3表示循環に案内の文言を合わせる | 必須 |
| 5 | 詳細パネルは、広いカードでは横並びを残す | 推奨 |
| 6 | 「トップバー1本・サイドバー1つ」を5配置で数えて確認する | 推奨 |

## 1. 最小は「非表示」ではなく「小片」

ユーザーの指示は「トグルで固定と最小を切り替え」で、消すことは求めていない。現在の `applyAuxiliaryUi()` は、最小のとき時間の帯・カード表示バー・ライブ HUD を `hidden` にしている。オムニナビだけが「場所」ボタンを残していて、これが正しい形。

消えると困る状態が2つある。

- **期間と照らし**: 時間の帯は期間（7日・30日・すべて）と「照らすのをやめる」を持つ。帯が消えると、絞り込み中であることが画面のどこにも出ない。カードが見当たらない理由が分からなくなる。
- **入力待ちの件数**: HUD 配置の「N 件 入力待ち」が消える。質問待ちに気づくことはこの構想の中心なので、最小でも残す。

修正案:

- 最小のとき、各要素は1つの小片を残す。置き場所はトップバーの中で、新しい行は作らない。
- 小片は要素が持っていた状態を1語で示す。例: 「期間 30日」「照らし中 11/12」「入力待ち 2」。
- 小片を押すと、その要素が領域を予約しないポップオーバーで開く。閉じると最小に戻る。固定は別の操作にする。
- カード表示バーは `1 2 3` のキーがあるので、小片は現在の表示名だけでよい。

受け入れ条件: 最小の状態で、期間が絞られていること、照らし中であること、入力待ちの件数が、ポインターを動かさずに読める。

## 2. 一括トグルと個別の開閉

`setAuxiliaryMode()` は `setKeyGuidePlace({ min })` を呼び、キー案内の開閉を毎回上書きする。計画の「既存の開閉を維持」と合わない。キー案内だけ開いた人が一括トグルを押すと、意図しない組み合わせになる。逆に、時間の帯だけ固定したい人は、HUD とカード表示バーも一緒に戻される。

修正案: 固定／最小は要素ごとに持つ。`Alt+Shift+U` とトップバーのボタンは「すべて最小」「すべて固定」の一括操作として残す。一括のあとに個別で変えた選択は、次の一括まで保たれる。保存する値は要素ごとの対応表1つにする。

要素ごとにするのが重ければ、最低限、一括トグルはキー案内に触れない。

## 3. 「仕事にまとめる」の既定の選択

`workBundlePicker()` の先頭は「いまの仕事（選ぶと紐付けを解除します）」で、ピッカーは先頭を選択した状態で開く（`popover.js` の `active = 0`）。すでに仕事に入っているセッションで `x` → `Enter` と押すと、紐付けが外れる。取り消しはあるが、既定の一手が「外す」になるのは「まとめる」という名前と逆。

修正案:

- 「いまの仕事」は選べない見出し行にするか、選んでも何も変えない。
- 解除は「この仕事から外す」という独立した項目にして、一覧の末尾に置く。
- 開いたときの選択は、候補があれば最初の候補、なければ「新しいタスクカードにまとめる」。

## 4. `i` の循環と案内

`toggleBoardView()` はボード → 時間軸 → ガントの3循環になった。一方、キー案内は時間軸の行で `i` を「ボード」、既定で「ボード／時間軸」と出す。時間軸で `i` を押すとガントへ行くので、案内と動作が食い違う。前回 0.29.79 で2方向に直した契約を、今回また変えている点も記録が要る。

修正案: 循環は3表示のままでよい。案内は「次に行く表示の名前」を出す。`docs/ui-components.md` の `i` の契約も同じ変更で更新する。ボードへ一手で戻る経路（⌘K の表示切替）が残っていることを試験で押さえる。

## 5. 詳細パネルの重なり

`.th-side` は幅に関係なく、常に会話の上へ重なる形になった（幅 360px または 85%）。初期に閉じる変更は指示どおり。ただし拡大したカードは幅に余裕があり、重ねると会話の右側を隠すだけになる。変更（`f`）やターミナル（`t`）を会話と見比べる使い方も失われる。

「固定領域を減らす」は、初期に場所を取らないことで満たされる。開いたあとの置き方まで重ねる必要はない。

修正案: カードの幅が広いとき（従来の境目 880px より上）は横並びを残す。狭いときだけ重ねる。入力欄の送信ボタンにパネルが重ならないかは、実画面で確認する。

## 6. 固定領域を配置ごとに数える

計画の検証に「5配置」はあるが、何を数えるかが書かれていない。次を受け入れ条件にすることを提案する。

- 最小の状態で、場所を予約する領域はトップバー1本とサイドバー1つだけ。残りは本文（一覧とカード）。
- HUD 配置は、固定にすると全幅の行が1本増える。これは利用者が選んだ結果なので許容する。最小のときは 1. の小片になる。
- レール配置は、レールをサイドバーの中へ入れた現在の変更でよい。
- オムニ配置はサイドバーがない。ドックは「場所」ボタンに畳まれ、ボード下の余白 152px を 12px に戻した変更でよい。

## そのほか、短く

- **横幅の内訳**: 1280px の時間軸では、サイドバー 260px と一覧 256px で約4割を使う。浮いている要素を畳んでも、会話の横幅はほぼ変わらない。前後の計測では、縦と横を分けて記録してほしい。横が増えていなければ、そう書く。
- **ガントで選択したとき**: 帯の列が 240〜340px に縮み、名前の列が 42% を取る。時間の帯として読める幅が残るかは実画面で見る。
- **Q1〜Q3**: 「全体構想を完成」の指示は、既定の表示（Q1）、同名カテゴリの自動合流（Q2）、ガントの名前（Q3）の決定を含んでいない。計画にも記載がないので、PR 本文に「未決のまま」と明記する。既定の表示は黙って変えない。

## 評価のときに見るもの

隔離プレビューを受け取ったら、1280×800 のライトとダークで次を歩く。旧 4633 は使わない。

1. 最小で開く。期間・照らし・入力待ちが読めるか。小片から開いて閉じる。
2. 一括トグルと個別の開閉を交互に押し、再読み込み後も選択が残るか。
3. 仕事に入っているセッションで `x`。既定の選択と、まとめる → 取り消す。
4. ⌘K でアーカイブ済みを探して開き、戻る。
5. `i` で3表示を一周。案内の文言と動作が合うか。
6. ガントに固定進捗と未来の帯が残っていないか。欠測の表示。
7. 220 往復の会話で、下書き・読む位置・入力欄のフォーカス。詳細パネルを開いて閉じる。

外部アプリの起動、実会話への送信、承認は行わない。
