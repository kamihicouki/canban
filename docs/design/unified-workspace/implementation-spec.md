## U1 待ちが読める行と、仕事の入れ子

### データ

`server/signals.mjs` の `wait` は種類（`'question' | 'plan' | null`）だけを持つ。質問文を足す。

- `signalsView()` に `waitText: string | null` を追加。最後に残っている問いの本文を、空白を畳んで120字で切る。
  - Claude: 未回答の `tool_use`（`AskUserQuestion`）の `input.questions[0].question`。
  - Codex: `request_user_input`／`request_user_input_async` の問いの本文。形が違えば `null`。
  - Antigravity など: `ask_question` 系ツールの引数に本文があればそれ、なければ `null`。
  - 計画の確認（`ExitPlanMode`）は `null`（本文を要約して作らない）。
- 選択肢は `waitOptions: string[] | null`（最大6件、各40字）。取れなければ `null`。
- `cardSignals()` がボードのカードへ通すこと。既存の利用者（`card-face.js` の「質問への回答待ち」）は変えない。
- 回答が届いたら消えること（既存の `asks` の削除に従う）。
- 追加だけなので移行は不要。古いクライアントは無視する。

### 行（`ui/inbox.js` の `inboxRow`）

- 2行目 `.irow-w` を、区分が 要対応／実行中 の行にだけ出す。文言は純粋関数 `rowWaitLine(card)`（`ui/lifetime-model.js`、試験対象）で決める。

| 条件 | 2行目 | 色 |
|---|---|---|
| `waiting` かつ `waitText` | `質問: ` + 本文 | 入力待ちの色（既存トークン） |
| `waiting` かつ `signals.wait === 'plan'` | 計画の確認待ち | 同上 |
| `waiting` それ以外 | 入力待ち | 同上 |
| `aborted` | 中断 | エラーの色 |
| `running` かつ `activity` | `activity` | 通常 |
| `statusKnown === false` | 状態は未取得 | 薄い |
| それ以外 | 出さない | — |

- 1行で切る。行の高さが増えるのは 要対応／実行中 だけ。
- 既存の `title`（ツールチップ）に2行目の全文を足す。

### 仕事の入れ子

- タスクカードの行の下に、紐付いたセッション `card.links` を子の行 `.irow.irow-sub` として並べる。子は `faceGlyph`・`faceWho`（AI App・利用面）・2行目（上の表と同じ規則）・時刻。
- 並びは、入力待ち→中断→実行中→新しい順。3件まで出し、残りは「ほか N」（押すと全部出す。開閉は行の中だけの状態で、保存しない）。
- 子の行は `role="option"`、`data-card-id` はセッションのID。`j`／`k` は親→子→次の親の順に進む。子を選ぶと、そのセッションを右にドッキングする（既存 `inboxSelect`）。親を選ぶとタスクを開く（既存どおり）。
- 親の「N セッション」の文字は残す。置く区分は既存 `timeGroupOf`（子の状態を見る）のまま。
- 子がフィルターで隠れている場合も、親の件数は `links` の全数ではなくボードが返した `links` に従う（既存のフィルター契約を変えない）。

### ドッキングしたカード（`ui/thread.js`）

- 入力待ちで `waitText` があるとき、入力欄の上の既存の待機表示の位置に、質問文と選択肢を読み取り専用で出す。見出しは「質問（元アプリで答えます）」。
- 承認・回答のボタンは置かない。既存の「アプリで答える」をそのまま主操作にする。
- `signals.wait` が立っている間は「答える」（`paintChoices()`）を出さない既存の規則を維持する。

### 利用面のバッジ（確認事項）

`inferSurface()`（`server/board.mjs`）は Codex の `source`／`threadSource` を見ない。架空データでは `source:'vscode'` が `CLI` と出た。実機の Codex Desktop／CLI が状態DBに書く値を確かめ、区別できるなら Codex の分岐を足す。区別できないなら変更せず、PR にその旨を書く。推測で `App` にしない。

### 受け入れ条件

- 質問待ちの Claude セッションの行に「質問: …」が出る。回答が届くと消える。
- 質問文が取れない入力待ちは「入力待ち」だけが出る（空の「質問: 」を出さない）。
- 実行中の行はいまの動き、応答済み・待機中の行は1行のまま。
- 2セッションを持つタスクが1つのまとまりで出て、子それぞれに AI App・利用面が付く。子の1つが入力待ちなら親は「要対応」に置かれる。
- `j`／`k` で子へ入れる。`Enter`・`r`・`d`・`1 2 3` は選んだ行に対して従来どおり働く。
- 長い質問文（500字）で行が1行に収まり、レイアウトが崩れない。
- 状態未取得のセッションは「状態は未取得」と出て、要対応にも実行中にも入らない。
- 試験: `tests/signals.test.mjs`（`waitText` の取得・消去・形の不一致で `null`）、`tests/lifetime.test.mjs`（`rowWaitLine`）、`tests/board-smoke.browser.mjs` に時間軸の入れ子と2行目の歩行を追加。

## U3 仕事にまとめる

### 候補（`ui/work-bundle-model.js`、純粋関数）

```js
// session: ボードのセッションカード。tasks: ボードのタスクカード（links を含む）。
workSuggestions(session, tasks) -> [{ taskId, strength: 'strong' | 'weak', reason: string }]
```

- `strong`: タスクの `links` に、同じマシン（`host?.id ?? 'local'`）・同じ作業フォルダー（`cwd` の完全一致）・同じブランチ（空でない）のセッションがある。理由は「同じ作業フォルダーとブランチ: 〈末尾のフォルダー名〉 · 〈ブランチ〉」。
- `weak`: マシンと作業フォルダーだけ一致。理由は「同じ作業フォルダー: 〈末尾名〉」。
- `cwd` が空・クラウド・`statusKnown === false` のセッションは候補を出さない。
- タイトルの一致・類似は使わない（同名でも別の仕事）。`repo` が両方にあり一致する場合に `weak` へ含めるかは、基点の `repo` の取得範囲を見て決めてよい（ローカル main の元リポ解決は移植しない）。
- 並びは strong→weak、同じ強さの中はタスクの更新が新しい順。最大5件。
- すでに紐付いているタスクは「いまの仕事」として先頭に出し、選ぶと紐付けを外す。

### ピッカー（`ui/work-bundle.js`、レイヤー4、既存 `popover()` のピッカー形）

- 見出し「仕事にまとめる」。区分は上から「候補」「新しいタスクカードにまとめる: 〈セッションのタイトル〉」「すべてのタスクカード」。文字入力で絞り込み、`↑↓`・`Enter`・`Esc`。
- 既存タスクを選ぶ: `canban_link_session({ taskId, sessionId })`。別のタスクに紐付いていた場合は移動になる（既存の制約）。行に「〈元のタスク〉から移動」と出す（`taskLinkMenu` と同じ表記）。
- 新しくまとめる: `canban_create_task({ title: セッションのタイトル, directory: セッションのカテゴリ, clientRequestId })` →成功後に `canban_link_session`。リストはセッションがいまいるリスト。`clientRequestId` で二重作成を防ぐ。作成に成功して紐付けに失敗したら、作ったタスクを残したまま失敗を伝える（黙って消さない）。
- 完了: トースト「〈タスク名〉にまとめました · 取り消す」。取り消しは `canban_unlink_session`。この操作で作ったタスクで、タイトル・説明・紐付けがその後変わっていなければ `canban_delete_task` も行う。移動だった場合は元のタスクへ紐付け直す。
- まとめた後は、時間軸の選択をそのセッションの子の行に保つ。開いているカード・下書き・読む位置を失わない。
- 候補は提示だけ。開いただけ・選択を動かしただけでは何も保存しない。

### 入口

- キー `x`: 時間軸の行・ボードで選んだセッションカード・開いているセッションカード。**実装前に `SHORTCUTS` と `tests/shortcuts.test.mjs` で衝突を確かめる**（基点で読んだ範囲では `ui/keyboard.js`・`card-overlay.js`・`inbox.js`・`thread.js`・`slack.js` に `x` の割り当てはない。ターミナルの `Shift+X` とは別）。衝突があれば `Shift+B` を代わりにし、PR に書く。
- ⌘K: 「仕事にまとめる」（セッションを選択中・開いているときだけ）。
- 詳細パネルの「タスクカード」の選択（「（タスクカードに紐付けない）▾」）は、同じピッカーを開く行に置き換える。別の部品を残さない。
- タスク側の「＋ セッションを紐付ける」（`taskLinkMenu`）とドラッグでの紐付けは向きが逆の操作なので残す。
- キーの案内と `SHORTCUTS` に追記する。
- タスクカード・dot・クラウドのセッション・サブエージェントでは無効にし、理由をヒントに出す。

### 受け入れ条件

- 同じフォルダーとブランチのセッションを持つタスクがあると、根拠の文つきで候補の先頭に出る。
- 同名で別フォルダーのタスクは候補に出ない（検索すれば選べる）。
- 新しくまとめると、タスクが1枚でき、時間軸でそのセッションが子として入れ子になる。
- 取り消すと、元の姿（独立した行、タスクなし）に戻る。移動の取り消しは元のタスクへ戻る。
- ピッカーを開いて `Esc` で閉じると、何も変わらない。
- 2回続けて `Enter` を押してもタスクが2枚できない。
- 手でまとめた／外した結果が、再読み込み・別クライアントでも保たれる。候補はその後も自動で紐付けない。
- 試験: `tests/work-bundle.test.mjs`（`workSuggestions` の強弱・除外・同名別フォルダー）、`tests/tasks.test.mjs`（作成＋紐付け＋取り消しの往復）、`tests/shortcuts.test.mjs`、ブラウザ試験にピッカーの開閉・まとめる・取り消すを追加。

レイヤー4（ピッカー）、5（⌘K）。キー `x`。

| 状況 | ボタン | 補足（`title` と、無効時は隣に1行） |
|---|---|---|
| デスクトップで同じ会話を開ける | 〈AI App〉で開く | — |
| デスクトップは同じ会話に届かず、新規になる | 同じフォルダーで新しく開く | 「この会話は〈AI App〉では直接開けません。続きはターミナルで再開できます」 |

| 入力待ち | 〈AI App〉で答える | 質問・承認は元アプリで |

| `unknown` | 無効 | 「開けるか確認できていません: 」＋`reason` |

- 開いた結果は「開く操作を行った」まで。実行済み・再開済みと書かない（既存の Desktop／CLI の結果表記に合わせる）。
- 狭い幅では文字を畳んでアイコンと `o` だけにし、`title` と `aria-label` に全文を残す。

## U4 探し直す

- ⌘K（`commandPalette()`、`ui/keyboard.js`）のカード検索に区分「ボードの外」を足す。入力が2文字以上のとき、200ms の間を置いて `canban_search({ q, days: 0, includeArchived: true, limit: 20 })` を呼び、いまのボードにないカードだけを出す。古い応答は捨てる。
- 行は、状態の記号・タイトル・AI App と利用面（文字）・理由の印（「アーカイブ済み」「30日より前」「絞り込みの外」）・時刻。既存の「カード」区分の行にも AI App と利用面を文字で足す（いまは色の点だけ）。
- 選ぶとそのカードを開く。ボードの絞り込みや期間は変えない（時間軸では既存の「行にないカードはその場に開く」扱い）。
- `canban_search` が返す行に `agent` はあるが `surface`・`archived`・`status` がない。足りない項目を返り値に追加する（追加のみ、既存の項目は変えない）。`tests/tools-list.json` と `tests/mcp.test.mjs` を合わせる。
- 「本文」チェックが入っているときの本文検索は既存の索引（直近90日）に従う。区分の末尾に「本文で探せるのは直近90日です」と出す。
- サイドバーの「アーカイブ済みも表示」は唯一の絞り込みの入口として残す。時間軸に別の切り替えを足さない。
- アーカイブ済みの印: `card.archived === true` の行（時間軸・休眠の1行）とカード3段目に「アーカイブ済み」を文字で出す。`canbanArchived` は別の印にしない（既存の扱いを変えない）。
- アーカイブ状態が取れないセッション（Claude で Desktop のメタデータがない等）には印を付けず、詳細の元アプリ欄の「未取得」に任せる。

### 受け入れ条件

- 既定の絞り込みのまま、⌘K でアーカイブ済みのセッションと31日以上前のセッションがタイトルから見つかり、理由の印が読める。
- 選ぶと開け、閉じるとボードの位置・選択・絞り込みが元のまま。
- 速く打っても古い結果が残らない。検索が失敗したら区分に失敗を出し、既存の区分は使える。
- 「アーカイブ済みも表示」を入れた時間軸で、アーカイブ済みの行に印がある。
- 試験: 検索の返り値の追加項目、パレットのモデル（ボード内の重複を除く）の単体試験、ブラウザ試験に「アーカイブ済みを⌘Kで開く」を追加。

## U5 流れの表示を観測値だけにする

`ui/gantt.js` を書き直す。名前と入口（表示の切り替え、`i`）は変えない。

- **消すもの**: 進捗の％（一覧の列と帯の塗り）、`card.status === 'done'`、最小幅96pxで作る帯、今日より右へ伸びる帯、ホバーの「タスクが進行中です。…」。
- **帯**: セッションは `createdAt` から `updatedAt` まで。`createdAt` がなければ `updatedAt` の位置の点。実行中・入力待ちは右端を今日の線まで伸ばし、端を状態の記号にする（「いま続いている」は観測）。それ以外は今日の線を越えない。1日未満は最小の幅（点）で描く。
- **タスクの行**: 子の帯を包む枠（最も早い開始〜最も遅い終わり）。子がなければ帯なしで「セッションなし」。
- **期限**: `due` があるカードだけ、その日に印。過ぎていれば色と文字（「期限超過」）。予定の帯は描かない。
- **一覧の列**: 状態の記号、タイトル、AI App・利用面、時刻。入力待ちは時間軸と同じ色と2行目（U1 の `rowWaitLine`。U1 が未マージなら状態名だけ）。
- **範囲**: 時間の帯の期間（7・30・90日・全期間）に合わせる。固定の22日をやめる。別の期間設定を足さない。
- **凡例**: 見出しに1行「帯は観測した活動の期間です。予定ではありません」。
- **色**: `ui/base.css` のトークンだけ。ライト・ダークの両方で定義する（ローカル main `c6d1ed7` の意図。移植か書き直しかは差分を見て決める）。Tailwind 風のクラス名（`text-[10px]`、`bg-black/40`、`text-sky-300`）は基点に定義が見当たらないので、既存のクラスかトークンに置き換える。
- **状態**: `ui/boot.js` の共有UI状態の復元が `board`／`timeline` しか受けない。`gantt` を受けるようにし、未知の値はボードにする。
- **キー**: `i` の巡回（ボード→時間軸→ガント）は維持。一覧で `j`／`k`・`Enter`・`r`・`d`・`1 2 3` が時間軸と同じに働くこと（いまは行の `click` と `dblclick` だけ）。行に `role="option"` と `tabindex`。
- **文書**: `docs/ui-components.md` にガントの受け持ち（レイヤー1、右は2の層をドッキング）、`AGENTS.md` の「時間・空間・情報の寿命」に1項、`SHORTCUTS` の `i` の説明を3表示に合わせる。
- 取得できない区間を実行・待機として補完しない（ui-components.md「活動時間軸の設計段階」の契約）。

### 受け入れ条件

- 画面のどこにも、観測していない数値（％）と未来へ伸びる帯がない。
- 3日前に終わったセッションの帯は3日前で終わる。実行中のセッションだけ今日の線に届く。
- 期限のないカードに期限の印がなく、期限のあるカードにだけある。
- `createdAt` のないカードは点で描かれ、ツールチップに「開始の時刻は未取得」。
- ライト・ダークの両方でトークンの色になる。
- ガントを選んで再読み込みしてもガントのまま。別クライアントでも同じ。
- 0件のとき「表示するカードがありません」。500件で描画が詰まらない（bench の前後比較を PR に書く）。
- 試験: 帯の位置と幅を返す純粋関数（`ganttBar(card, range, now)`）の単体試験、`tests/ui.test.mjs`、ブラウザ試験にガントの歩行。

## 2. 横断の受け入れ条件

brief が挙げた場面ごとに、第一段階の終わりで成り立つこと。

| 場面 | 成り立つこと | 単位 |
|---|---|---|
| 取得不能 | ソースの読み取り失敗は既存の警告に出る。失敗したハーネスのセッションを「なし」と数えない。状態未取得は「状態は未取得」で、要対応・実行中に入れない | U1 |
| 実行中 | 行にいまの動き。帯は今日まで。追加依頼は既存どおり不可で理由が出る | U1・U5 |

| 複数ハーネス | 同じ仕事の Claude・Codex・Antigravity のセッションが1つのまとまりで見え、子ごとに AI App と利用面が読める。まとめるのは人、候補には根拠 | U1・U3 |

## 3. 互換性と移行

- スキーマの変更は追加だけ: `signals.waitText`・`signals.waitOptions`、`canban_search` の返り値の `surface`・`archived`・`status`。保存データの変更なし。移行なし。旧版へ戻しても壊れない。
- `links`・カードID・保存ビュー・共有UI状態のキーは変えない。`boardView` は `gantt` を共有UI状態でも受けるようにするだけ。
- MCP ツールの追加・削除なし。`tests/tools-list.json` は `canban_search` の出力の説明が変わる場合だけ更新。
- Chrome 拡張・Codex プラグイン・MCPB の配布形に影響しない。ローカル拡張への反映（`npm run update:local`）はこのブランチでは行わず、main へ取り込むときの手順に従う。

## 4. 実装後の評価（Claude 側）

各 PR のあと、同じ架空データ（Codex 5・Claude 5・Antigravity 2、アーカイブ2、長会話1、同じ仕事の3セッション）で次の経路を 1280×800 のライト／ダークで歩き、design.md §2.2 の7項目と比べる。

1. 開く→いま待たれているものを、何もクリックせずに言えるか。
2. 質問の中身を、元アプリへ行かずに読めるか。
3. `o` で続ける経路と、開けない理由が読めるか。
4. 「決済」の3セッションを `x` で1つにまとめ、取り消せるか。
5. アーカイブ済みの設計メモを⌘Kで開けるか。
6. 流れの表示に、観測していない値がないか。

評価に使う架空データの作り方は、`tests/helpers.mjs` の `makeFixtures()` に Codex・Claude・Antigravity の行を足す形で試験側へ持つと、ブラウザ試験と評価で同じものを使える（`tests/layout-fixture.mjs` と同じ置き方）。

## 5. Codex と決めてよいこと／人間に確認すること

- **Codex が決めてよい**: `x` が衝突した場合の代替キー、`waitText` の各ハーネスでの取り出し位置、`repo` 一致を弱い候補に含めるか、`c6d1ed7` を移植するか書き直すか、単位の順番と PR の分け方、文言の細部（既存の用語表に合わせる）。
- **人間に確認する**（design.md §10）: 既定の表示を時間軸にするか（Q1）、同名カテゴリへの自動合流を残すか（Q2）、ガントの名前（Q3）。どれも U1〜U5 を止めない。
