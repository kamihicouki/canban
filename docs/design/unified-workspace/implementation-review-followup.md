## B1 解消

- 1280×800 ライト: ▾ は x 818–846、主ボタンの枠（650–846）の内側。「思考」は 850 から。▾ の左端・中央・右端の3点とも最前面は ▾ 自身。
- 実際にポインターでクリックして「開く経路」が開いた。「思考」の列は開いたまま変わらなかった（誤って「思考」を押していない）。ダークでも同じ。

- 理由の行は 12px になっている。

## B2 解消

- Claude「README 修正」の行にフォーカスを置いて `o`。ライト・ダークとも次が同時に起きた。
  - トースト「Desktop の接続を確認してください」。
  - 「開く経路」が開き、フォーカスは最初の使える経路「ターミナルで再開」。無効の経路（Claude で答える、分割）には理由が付いている。
- `Esc` で一覧だけが閉じ、フォーカスは元の行へ戻る。右のカードは1枚のまま。
- 主ボタンを使える経路へ自動で差し替える提案を採らなかった判断は妥当。経路が変わるとアカウントと許可の境界も変わるので、人が一覧から選ぶ形のほうが design.md の「勝手な実行を生まない」に合う。`o` 1回で理由と選択肢が出るので、続ける体験も止まらない。
- 気づいた点（後続でよい）: フォーカスが使える経路に乗るので、`o` → `Enter` の2打で起動に進む。明示の操作ではあるが、トーストを読む前に `Enter` を押すと意図しない経路で開く余地がある。経路の名前が行に出ているので現状で許容できる。

## B3 解消（コードと試験）

- `server/status.mjs` の `settle()`: `running` は15分で `idle`（従来どおり）、`waiting` は `RECENT_MS`（24時間）を超えたときだけ `idle`。
- `tests/status.test.mjs`: 15分超で `waiting` のまま、24時間ちょうどで `waiting`、24時間＋1msで `idle`、回答・新しいターンで待ちが消える、を Codex・Claude の両方で確かめている。`tests/status.test.mjs` と `tests/signals.test.mjs` をこちらで実行し、15件すべて成功。
- 画面では、作成から9〜10分の時点で 要対応・入力待ち・「質問: …」を確認した。15分を越えた状態は画面では見ていない。
- 波及の確認事項: `settle()` は `server/dispatch.mjs`（追加依頼の送信前の判定）でも使われる。入力待ちが長く残る分、その間の追加依頼は従来どおり順番待ちになる。安全側の変化だが、意図した範囲かは Codex 側で見ておいてほしい。
- 実機の Desktop で、質問を放置した会話が本当に書き込まれないか、Desktop 側の状態（`desktopStatus`）と食い違わないかは未確認のまま。
