# 時空間とターゲットを軸にしたCanban実装提案

状態：共同検討を反映した提案。実装・DB移行・外部連携の開始は含まない。2026年10月30日。

## 提案の中心

Canbanの同じボードに「ライフタイムライン」を描く。横に時空間、縦に望むことと取り組んだこと、その交点に課題・行動・出来事を置く。最初の描き方は織物と楽譜を組み合わせ、ほかの4案も同じ記録と選択を使って展開する。

既存のタスクカード・セッション・一覧・更新履歴を、人生の達成実績へ自動変換しない。本人が望むターゲットとのつながりを付けることで、仕事の履歴が人生の文脈で読めるようになる。

## 1 横軸は時空間ライン

主座標のxは時間とする。場所は時間に沿う細い文脈帯、区間の注記、選択時の場所表示として重ねる。時間と地理を一つの数値軸に変換しない。縦軸はターゲットのために保つ。

例：10月30日14時〜16時・自宅・オンラインで家族と話した。xは14時〜16時、場所文脈は「自宅」「オンライン」。相手の所在地は推測しない。旅行や移動は複数区間に分け、同時に関わる場所も許容する。

瞬間、区間、日だけ分かる記録、時期未定、開始だけ分かる継続を区別する。日付だけの記録に0時という精密な時刻を捏造しない。UTCの瞬間にはIANAタイムゾーンを持たせ、日・月・年の精度しかない記録は暦の値と精度を保持する。近似範囲は厳密な実施時間と別にする。

過去にも当時の計画や未確認情報はある。過去/未来という位置だけで事実/仮説を決めない。「いつ起きたか」と「いつ記録・訂正したか」の両方を残す。

場所を取得する外部連携は初回に含めない。本人が入力した粗い場所名から始め、精密位置や他者の情報は必要になったときだけ明示的に扱う。

## 2 縦軸はターゲットライン

ターゲットは「家族との時間を持つ」「独立して働く」など、望む変化や維持したい状態。行の順序は本人が決め、包含のまとまりは畳める。カテゴリ、リスト、既存タスクの実行先には流用しない。

「なにをしたいか」は行の名称と薄い継続帯、「なにをしたか」は実績の点や区間で表す。点の数から達成度や人生の良し悪しを計算しない。期限のある達成型と、終点のない維持型を扱う。

同じ「家族と話す」が、住まいと家族関係の両方に貢献してよい。代表行に量を持つドットを一つ、ほかの行には小さな参照ドットを置き、選択時だけ同じIDの糸で結ぶ。参照側で全額の面積を複製しない。代表行は表示上の基準であり、ターゲットの重要度を意味しない。

ターゲットを休止すると、そのターゲットからの通常の問い・提案・促しを止める。共通行動の中止、ほかのターゲットの休止、過去記録の削除は起こさない。休止・再開・手放しは本人の明示操作で行う。

代表行が非表示になる場合は、表示中の関連行の先頭へ量を持つドットを表示上だけ繰り上げる。参照ドットも同じIDを選び、全行の対応点を照らす。フィルターで実体へのアクセスが失われたり、代表行の変更でコストの帰属が変わったりしない。

## 3 交点は課題への入口

交点に描く点や帯は「課題がその時間・場所で現れた記録」とする。一つの持続課題は何度も現れ、一つの行動にも計画と実績がある。課題の同一性を、画面上の点や座標と同一視しない。

選択で関係を照らし、既存タスクに結び付く記録は、共通のカード詳細で開く。そこに「なぜ（目的・理由）」「どのように（方法・計画）」「どのくらい（コスト）」「だれと（役割付きの参加者）」と根拠を置く。キャンバスに説明文や属性を常設しすぎない。

既存タスクにない観測は初回の読取モデルで扱い、変更は同じ作成ダイアログ/確認ダイアログを拡張して行う。ターゲット自体をタスクとして複製しない。ターゲットの行編集は行ラベルを入口にする小さなピッカーへまとめる。

計画と実績は別IDで保持し、実績がどの計画に応じたかを `fulfills`、改訂した計画を `replans` でつなぐ。予定をドラッグしても過去の実績は変えない。セッションの応答完了やCLI正常終了をターゲットの達成と扱わない。

この対応は多対多とする。一つの計画が複数回の実施に分かれたり、複数の計画を一度で実施したりしてよい。未実施・取消し・改訂を区別し、自動で失敗へ変換しない。遡及入力は発生日と記録日を併記し、集約にも「最近追記」を示す。任意の記録時点を再現するas-of表示は後続とする。

## 4 コストの視覚文法

| 視覚要素 | 初回の意味 | 制約 |
|---|---|---|
| 横位置 | 時刻または期間 | 表示の縮尺とタイムゾーンを明示 |
| 横の長さ | 経過期間・継続期間 | 作業投入時間や金額に置き換えない |
| ドットの面積 | 選択したコスト指標1種類 | 半径ではなく面積を量に比例。凡例と単位を併記 |
| 帯の太さ | 区間ごとの投入量または密度（後続） | 長さと太さの積が何を意味するかを定義してから導入 |
| 色 | 状態の一つの規約 | 既存テーマトークンを使う。量を色で見る場合は専用表示として切り替え、状態色と混ぜない |
| 形 | 行動・出来事・判断 | 色だけで意味を伝えない |
| 塗り・輪郭・線種 | 実績・計画・仮説 | 出所や確実性と組み合わせる。装飾で意味を変えない |

初回のコスト表示は「人の投入時間」または「金額」を1つ選ぶ。本人の時間、エージェントの稼働時間、暦の経過時間は別指標。複数人は人ごとの記録を持ち、必要なら人時として表示する。異なる通貨や時間と金額を、そのまま加算しない。見積と実績も別に集計する。

コストは `known`（値が0の場合を含む）、`unknown`（不明と分かっている）、`unset`（未入力）を区別する。初回は非負の投入コストだけを扱い、収入・返金・便益・達成度は別指標として後続へ送る。0や不明のドットも選択できる最小の当たり判定を持たせ、当たり判定の大きさを量の面積と混同させない。範囲見積と表示上限はその旨を表示する。

時間は根拠付きの実作業区間がある場合だけ重なりを処理する。本人の占有時間は区間の和集合、複数エージェントの総稼働量は資源ごとの加算で、別の指標とする。総量だけ分かる入力から、時間区間や配分を推定しない。共有された費用は同じcost IDへの参照とし、独立した支出との区別を保持する。

全体集計は実体ID・cost IDで重複除外する。ターゲット別コストの合算や自動配賦は初回には出さない。後続で配賦する場合は本人が配賦を選び、比率と合計の契約を定義する。

## 5 一つのデータから6種類の舞台へ

| 表現 | 使う場面 | 短期の表示 | 長期の表示 |
|---|---|---|---|
| 織物 | いつ、何が続き、分かれたか | 行動点・期間・選択周辺の依存 | 継続帯・束・転機 |
| 庭 | なぜ、何とつながるか | 選択した枝と日付付き記録 | 課題のまとまりと主要な関係 |
| アトラス | 全体の領域を見渡す | 選択領域の局所図 | 領域と橋、時間ナビゲーター |
| スコア | 並行、反復、休止を読む | 日ごとの点と同時進行 | 反復の束と明示した休止 |
| 路線図 | 前提と選択肢を辿る | 行動・判断・乗換 | 大きな道筋と分岐 |
| 見開き | 転機や本人の意味づけを振り返る | 出来事と出典、本人の言葉 | 編集した章と主な出来事 |

庭・地図・路線図の空間距離は時間ではない。時間ナビゲーターと日付を残し、実際の地理の地図とも区別する。自由配置の座標は表示設定として保持し、移動で実際の日付・場所を変えない。時刻を動かす操作は明示的な計画編集に限る。

これらは `ui/layouts.*` のボード5配置とは別の表現である。初回に6種類のビュー切替メニューを並べない。織物/スコアの共通キャンバスを作り、その後、選択した課題を庭で広げたり、同じ範囲を地図で俯瞰したりする同一舞台内の遷移を検証する。

## 6 日から数十年までの表示

近景は一つの記録、中景は週・月の束、遠景は年や章と領域へ意味ズームする。集約は暦に整列した決定的なバケットIDを持ち、表示中のパンだけで境界が変わらないようにする。日付を跨ぐ量は、区間の根拠がある場合にその境界で分割する。

選択は時空間記録IDで保持する。縮小時はそれを含む束を照らし、拡大すると同じ記録に戻る。ターゲット順序を保存し、行内の重なりは安定スロットを保持して局所更新する。過去への新規記録挿入で全レーンを貪欲再計算しない。再配置は本人の明示操作とし、縮尺を超える永久のピクセル位置までは保証しない。

未記録の割合は、網羅性の分母がないので作らない。件数、期間、根拠と、分かっている不明/未入力を表示する。画面外を描かず、集約の上限を設け、詳細は必要な範囲だけ取得する。無作為な点の間引きで全体量を偽らない。

将来の性能受け入れ条件案：30年・5,000実体・20,000関係で、初回の描画ノードは1,500以下、操作対象は必要範囲に限定。基準マシン・ブラウザーを固定した計測で操作応答p95 100ms以内を暫定目標にする。これは未測定の目標であり、達成済みの数値ではない。

## 7 既存Canbanへの接続

| 現在の所有箇所 | 提案 |
|---|---|
| `ui/lifetime.js` の `boardView=board\|timeline` | 維持する。時間軸内部の `timelinePresentation=activity\|life` を追加する案。既存の履歴表示と人生表示を選べるようにする |
| `ui/board-render.js` | 人生表示の入口だけを追加。描画や集計本体を肥大化させない |
| `ui/lifetime-model.js` | 寿命・更新日のグループを担当し続け、人生の状態や実績時間に流用しない |
| `server/store.mjs`、`server/sqlite-backend.mjs`、worker/client | 同じ書込経路・トランザクション・フェンスを経由して新しいレコードを扱う |
| `server/tools/tasks.mjs`、`server/tools/board.mjs` | 既存カード操作は維持し、範囲・ターゲット・粒度を指定するlife専用の読取/APIを別モジュールに足す |
| `ui/thread.js`、`ui/card-overlay.*` | 既存タスクとセッションの詳細・入力・下書きを再利用する |
| `ui/keyboard.js`、`ui/key-guide.*` | 同じキー案内と⌘Kへ追加し、既存文脈のキーを奪わない |

新規の責務案：`server/life-model.mjs`（型・検証）、`server/life-store.mjs`（同じDBへのアクセス）、`server/life-query.mjs`（区間・集約）、`server/tools/life.mjs`（公開契約）、`ui/life-model.js`（表示ノードの純関数）、`ui/life-layout.js`（配置）、`ui/life-canvas.*`（描画と入力）。いずれも未作成の候補名。

表示ノードの生成は `(データ, viewport, zoom, selectionId) → nodes` とし、集計、配置、DOM/SVGを分離する。初回は描画数を絞ったSVGと、キーボードで辿れるDOMの一覧を同じモデルから作る案。量だけの装飾を描くCanvasは後続の計測次第で採用する。外部ライブラリーの選定は実装時に行う。

## 8 保存モデルと移行

提案するレコードは `life_targets`、`life_issues`、`life_occurrences`、`life_edges`、`life_contributions`、`life_places`、`life_place_stays`、`life_costs`、`life_card_refs`。既存のカードや `links` を複製しない。`life_card_refs` は実行/観測/根拠のroleを持ち、ソースが取得不能になっても出典と未取得状態を区別する。

現行の `task.target` はエージェント・ホスト・cwdなどの実行先である。人生のターゲットは `lifeTargetId` / `goalTargets` とし、このフィールドを上書きしない。

各記録は安定ID、revision、作成/記録時刻、出所、明示状態を持つ。関係は有効期間と訂正履歴を持ち、包含と厳密な前提の循環を拒否する。自由配置や表示の代表行は表示状態で、実績や費用を変更しない。

一例：

```json
{
  "id": "occ:example-family-talk",
  "issueId": "issue:example-home",
  "kind": "action",
  "basis": "actual",
  "time": {"start": "2026-10-30T05:00:00Z", "end": "2026-10-30T07:00:00Z", "zone": "Asia/Tokyo", "precision": "minute"},
  "lifeTargetIds": ["life:example-home", "life:example-family"],
  "placeRefs": ["place:example-home", "place:example-online"],
  "cardRefs": [{"cardId": "task:example", "role": "execution"}],
  "reason": "住まいと家族の過ごし方を考える",
  "method": "候補を見比べて話す",
  "participants": [{"ref": "person:self", "role": "participant"}],
  "costRefs": ["cost:example-self-time"]
}
```

この2時間の経過区間から、本人の投入時間を自動で2時間と決めない。投入量は別のコスト記録と根拠を必要とする。例のIDや人物は架空である。

現在はSQLiteスキーマv1で、新版DBを旧プログラムが拒否する。lifeを導入する場合は明示的なv1→v2の移行を作り、適用前に読取検査、SQLiteの整合したバックアップ、適用後の既存データ一致確認を行う。保存先は既存のデータディレクトリの契約を維持する。

新表の追加だけでも旧版へ単純に戻せるわけではない。戻す場合は移行前のスナップショットか検証済み互換エクスポートを使い、移行後の追加記録を失う可能性を説明する。旧クライアントの書込は版検査で拒否する。`readBoard`/`writeBoard` の既存ボード全置換でlifeレコードが落ちない保存経路を設ける。

本人が削除した内容を復元で再出現させない。内容を含まない削除記録を復元対象外の管理領域にも保持し、復元は隔離領域で削除を再適用・派生要約と索引を無効化した後にだけ公開する。これを保証できない旧版への復元は実施せず、消去済みの内容を除いた互換エクスポートを使う。バックアップの保持期限を定める。外部へ既に渡ったコピーまで回収できるとは扱わない。

安定スロットのキャッシュは保存版に紐付け、復元で無効になる場合は再配置の必要と差分を本人へ示す。本人以外の情報を取り込む共同編集や位置追跡は初回に含めず、AIは問い・下書きまでから始める。課題の包含で閲覧や実行の権限を継承しない。

既存カードの `updatedAt`、期限、アーカイブ、セッションの完了から人生の実績を作らない。初回は空のターゲットから始め、本人が既存カードを明示的に紐付ける。自動取り込みを追加する場合も出所付き候補にとどめる。

## 9 操作とレイヤー

アプリバーは1本、ボード面はレイヤー1、詳細はレイヤー2、作成/確認は3、行編集/表現のピッカーは4、⌘Kは5を維持する。全画面の舞台ではサイドバーを既存操作で畳める。新ページや第二のツールバーは作らない。

期間・縮尺の入口は時間の帯にまとめ、場所/ターゲットの絞り込みはサイドバーへ置く。コスト指標は量の凡例から一つ選ぶ。既存の状態や軸と混ぜた巨大な設定パネルを作らない。

キー案：`i` は既存のボード/時間軸切替を維持。点はTab→Enterで既存詳細へ。Escは最上位だけを閉じる。時間の帯・行ラベル・凡例の各ネイティブボタンをTab→Enter、ピッカーを矢印で操作でき、同じ操作を⌘Kとキーの案内に載せる。専用1文字キーは全SHORTCUTSと文脈を照合した実装PRで確定する。マウスやドラッグだけに依存しない。

## 10 導入順と受け入れ条件

1. **基盤**：型、空の保存領域、版付き移行、範囲読取、既存タスクへの明示リンク。実データの自動取り込みなし。
2. **最初の舞台**：ターゲット行と時空間の織物/スコア、日〜年の意味ズーム、場所文脈、既存カード詳細、実績/計画/不明の区別。両方の描画で同じモデルが使えるかを確かめる。
3. **量と関係**：1指標ずつのコスト面積、重複除外、参照ドット、選択周辺の包含/前提/支援/競合/代替。未確定関係は候補のままにする。
4. **広がり**：30年での集約・検索・局所更新を検証した後、庭・地図・路線図・見開きを順に試す。AIは根拠付きの問いと編集可能な下書きから始める。

検証は、同じ行動の多重所属で費用が増えないこと、計画改訂で実績が変わらないこと、通貨/単位/主体/見積実績の混合を拒否すること、明示休止と未記録の差、時期未定/日精度/DST/日付変更線/並行実行、旧ボードの往復と下書き保持、削除した参照と取得不能の違いを含む。

週と年の合計一致は、同じ範囲・同じ指標・同じ基底・同じ暦境界で、重なり処理と境界分割を揃えた場合に検証する。生の件数を足して一致させるテストにはしない。

UI実装時には `npm test`、`node --test tests/board-smoke.browser.mjs`、1280×800のライト/ダーク、ボード/時間軸の往復とキー操作を確認する。スケッチ6枚は受け入れ証拠の代わりにはならない。

## 共同検討で修正した点

Claudeのレビューから、場所区間の分離、計画と実績の別ID、役割付き出典、意味ズームの選択保持を採用した。一方で、新たな第3ページ、スキーマ管理の新設、旧版が新表を無視するだけの戻し方、貪欲配置による永久の位置安定、分母のない未記録割合は採用していない。現行コードと上記の契約に合わせて修正した。

## 現行資料との不一致

- `docs/ui-components.md` のカード内可動部品・列幅変更の記述は、`ui/thread.js` の共通スレッド表示と一致しない。`ui/card-overlay.js` の `paneLayout` に関するコメントも残っている。現行スレッド部品を再利用する。
- `docs/design/timeline-reading/README.md` のキーの案内の分だけstage/cardを空ける記述は、`ui/key-guide.js` の `keyGuideReserve() = {left:0,right:0}` と一致しない。現在の浮かせる挙動に従う。

現行の時間軸は更新日のグループで、時間の帯の全期間表示も最大90日の描画である。これは人生の任意の時間区間を描く機能ではなく、life専用の範囲読取と表示が必要になる。
