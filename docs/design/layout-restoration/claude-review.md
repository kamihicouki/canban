# Claudeとの設計・独立レビュー

2026-10-09、既存のClaude Desktop接続から、この案件専用の新しいチャットに依頼した。
Claude CLIは未ログインだったため使用していない。アカウント作成、認証、権限追加は行っていない。

[Claudeのレビュー](https://claude.ai/chat/be8adefd-40c2-4b30-8c70-2ca6f5433ce3)

共有したのは、この案件の要件、合成した4行の例、`buildBoard`と復元実装のコード抜粋だけ。
認証情報、実ユーザーのセッション履歴、他の会話、メモリは送っていない。

## 設計提案

- 状態帯：連続した時間に状態の区間を置き、観測できなかった区間を斜線にする。
- イベント譜：観測した開始・待機・入力待ち・終了などを記号として置き、状態の継続とイベントを分ける。
- 概観と比較レンズ：全体を圧縮し、選んだ行を同じ時間幅で比較する。

## 指摘と対応

| 指摘 | 今回の対応 / 次の実装での契約 |
|---|---|
| レイアウト切替からボード取得を呼ぶと、既読や自動化を変える可能性がある | 切替は保存済みUI設定と取得済みボードの再描画のみ。回帰テストで`load`やカード操作を呼ばないことを確認 |
| UI保存が`seenAllAt`などを上書きしないか確認する | Storeを使った統合テストで、全5種の保存前後のカード・既読・設定が同一であることを確認 |
| 未知のレイアウト値を表示の都合で書き戻さない | 生の保存値を保持し、Trelloへの表示上のフォールバックと明示的な選択を区別 |
| 旧版で設定が既に消えた場合は復元できない | 既存値が残る場合は再採用する。消失済みの値は推測で再生成しない |
| HUDは実行中カードで検証し、古いヘルパーへの参照を確認する | 合成の実行中セッションを追加し、廃止済み関数を現行の状態・エージェント表示に置換 |
| サンプル時刻だけでは区間全体を観測したといえない | `occurredAt`・`observedAt`・`fetchedAt`と観測窓を別に扱う。空白区間を埋めない |
| 後から回収したイベントを当時の観測と混同しない | 観測外の区間に入る回収イベントは輪郭などで区別する |
| 更新の古い状態と情報未取得を分ける | 古い最終既知状態は別フラグ。未観測・取得失敗を正常な待機にしない。消えた行を停止とみなさない |
| キャッシュを新しい観測として扱わない | 取得成功と観測時刻を分離し、ホストごとの失敗、時計ずれ、ログ保持期間を扱う |
| カードの手動状態はセッションの実行状態を表さない | プロジェクトの進行状態と、ソースセッションの実行状態を別に表示する |

新しい履歴投影は今回実装していない。3案の選択後、この契約に従って合成データの操作プロトタイプを作る。

## 復元実装の追加レビュー

同じチャットで `setLayout`、生値と表示値の分離、共有状態の保存・採用の抜粋を送り、独立に確認してもらった。
Claudeはコード全体を見ていないため、抜粋からの指摘には条件付きのものが多い。確認結果は以下。

| 指摘 | 照合結果 |
|---|---|
| 無効なIDを選ぶと未知の保存値がTrelloに置換される | 無効IDは無操作で返すよう修正し、テスト追加 |
| 起動と共有状態採用で型の扱いが違う | `null`や未知値も保持し、表示だけ正規化するよう統一 |
| 同じ配置の共有更新でもDOMを作り直す | 表示する配置が変わる時だけ作り直すよう修正 |
| 他の共有キーを適用する途中で配置を作る | 全キーを反映した後に配置を適用する順序へ変更 |
| 他画面から配置だけが変わる場合の動作が未確認 | 取得済みデータを再描画し、再取得しない経路を追加。フィルター変更の場合は既存の取得を維持 |
| 共有値がローカルに保存されない可能性 | 既存 `store.cache` が共有キーを先にローカルへ保存することを確認。初期同期前に共有保存しない既存のreadyガードも確認 |
| ボード未取得時にHUDが例外になる可能性 | `applyLayout` の `state.board` ガードと `paintLayoutChrome` の早期returnを確認。HUD保存値からの起動も合成プレビューで確認 |
| 旧IDと違う可能性 | 削除前のコードと照合し、5つのIDが同じことを確認 |
| 切替で入力・管理パネル・カード詳細が消える可能性 | 実際のカード返信と管理設定の下書きで、20方向の遷移を検証 |
| 旧アンカーが消えてメニューが残る可能性 | ピッカーは切替前に閉じる。選択後は新配置の同じ入口へフォーカスを移す |
| イベントやタイマーが蓄積する可能性 | 配置専用DOMにはボタンのハンドラだけを付け、window/documentの購読・タイマーを作らない。画面幅の購読は初期化時1回 |
| HUDがボード更新で変わらない可能性 | 共通 `render` の末尾でHUDを描き直す。対象は現在の絞り込み後のボードと一致 |
| 共有revisionの拒否後に保存値が勝手に巻き戻る可能性 | 既存の競合通知・同期停止・入力保護を維持。競合拒否時のStoreテストを確認 |

レビューは実装全体の承認ではない。コード全文や実データをClaudeに送らず、こちらのテスト・ソース確認で照合した。
