# Canban 実用性の検査と評価（0.25.3 → 0.26.0）

2026-10-08。このMacの実データ（`~/.canban` の複製）で 0.25.3 を動かし、機能・UI/UX・Chrome 拡張・Codex プラグイン・Claude 拡張（MCPB）・性能・コードを検査した。評価は「毎日、数十件のエージェントセッションを扱う道具として使えるか」を基準にする。

## 1. 結論

Canban の土台（3つのホストで同じボード、セッションの再開・追加依頼、リアルタイム表示、キーボード操作）は実用水準にある。実用を妨げていたのは機能の不足ではなく、次の3つだった。

| 種類 | 何が起きていたか | 0.26.0 での対処 |
|---|---|---|
| ムダ（増えすぎた選択肢） | レイアウト5種 × コンポーネントのスタイル8項目（4×2⁷）× 色3種で、組み合わせは 7,680 通り。⌘K にも切り替えが約20件。どれを選んでも中身は同じ | Trello 基調の1種類に統合。好みとして残すのは色だけ |
| ムラ（同じ役割の部品が別の作り） | セッション詳細はスレッド型、タスク詳細は旧来のモジュール型（つまみ・列幅・絵文字アイコン）。カードの面も「現行」と新しい面が並存 | タスク詳細もスレッド型に統一。カード部品の並べ替え機構は撤去 |
| ムリ（量に耐えない） | 30日で 254 件が表示され、受信箱 114・レビュー 91 枚。手で置いたカードは期限なく残る。時間を見る手段は「期間」の4択だけ | 寿命モデル・休眠の折りたたみ・時間の帯・時間軸を追加 |

## 3. 領域ごとの評価

5段階（5 が実用上問題なし）。

| 領域 | 0.25.3 | 0.26.0 | 根拠 |
|---|---|---|---|
| セッションの集約・再開 | 5 | 5 | 3ホストで同じボード。再開経路とキーが豊富で一貫している |
| 追加依頼（送信・キュー） | 4 | 4 | 権限はセッションのまま、1ターンずつ。許可待ちに答えられないのは仕様（アプリへ案内） |
| 情報量への耐性 | 2 | 4 | 寿命で密度を変え、休眠を畳む。データを動かさずにボードが軽くなる |
| 時間の把握 | 1 | 4 | 時間の帯（日ごとの棒・照らす）と時間軸を追加 |
| 一貫性 | 2 | 4 | 見た目1種類、詳細はスレッド型1種類。選択肢と分岐を撤去 |
| キーボード | 4 | 4 | `i`・`Esc`（照らす解除）・帯の矢印キーを追加し、配置用の9キーを削除 |
| 初回表示 | 2 | 4 | リモートは 1.5 秒で打ち切り、届いた時点で再描画 |
| Chrome 拡張 | 3 | 4 | ボタンを押すたびにタブが増えていた。開いているボードを前面に出すよう修正（権限は増やさない） |
| 狭い幅（Codex のサイドバー） | 2 | 4 | 幅 390〜480px でアプリバーが最大 325px はみ出していた。表示の切り替え・絞り込みのチップ・実行状況・既読・再読み込みも ⋯ に畳む |
| Codex プラグイン | 4 | 4 | サイドバーに常駐、既定プロンプトも妥当 |
| Claude 拡張（MCPB） | 3 | 3 | 常設の入口がなく、毎回チャットで開く（ホストの制約） |
| 開発・保守 | 2 | 3 | ベンチを復旧。UI は 37,095 バイト減（598,946 → 561,851）。`board.html` の一枚岩は残る |

## 4. 機能の整理（残す・まとめる・やめる）

| 機能 | 判断 | 理由 |
|---|---|---|
| レイアウト 定番・レール・オムニバー・ライブ HUD | やめる | 中身は同じで並べ方だけが違う。検証の手間が5倍になり、入口の重複を生みやすかった |
| ライブ HUD の「動いているセッションを常に見せる」 | まとめる | 寿命「動いている」として、時間の帯の件数とカードの面（計画・承認）に出す |
| ボードのカード 現行・コンパクト・リッチ | まとめる | 寿命が密度を決める（動いている＝リッチ相当、休眠中＝コンパクト相当） |
| その場返信の有無、変更のレビューの有無 | 残す（常に有効） | 使わない人の邪魔にならない。設定にする意味が薄い |
| カード詳細 モジュール、会話の表示 現行、入力欄 現行、タスク詳細 現行 | やめる | スレッド型・折りたたみ・チップに一本化 |
| 受信トレイ | まとめる | 時間軸として独立した表示に格上げ（`i`） |
| カードの高さ（揃える・内容に合わせる） | やめる | 密度は寿命が決める |
| レーン内のリストの高さ | 移す | レーンの設定なので、サイドバーの「レーン」に置く（レーンがあるときだけ） |
| 期間の絞り込みと「30日以内」チップ | 移す | 時間の帯に一本化（入口は1か所） |
| カード内の部品の並べ替え・列幅・高さ・開閉 | やめる | ムリな自由度。種類ごとのカードの幅と高さだけ残す |

## 5. 新しい設計：時間・空間・情報の寿命

Trello の「リスト＝空間」はそのまま残し、エージェントの仕事の量に合わせて「時間」の軸を足した。

- **空間（どこ）**：リストとレーン、サイドバーの絞り込み。従来どおり手で動かせる。
- **時間（いつ）**：ボードの上の時間の帯。寿命の段階ごとの件数、日ごとの棒、休眠の境、期間。段階や日を押すとそのカードだけを照らす。`i` で同じカードを時間軸（要対応・実行中・今日・昨日・今週・今月・それ以前）に並べ替える。
- **情報の寿命**：動いている → 新しい → 今週 → 休眠中。カードの面は寿命に合わせて情報量を変え、休眠したカードはリストの末尾に畳まれる。動けば戻る。データは移動もアーカイブもしない（エージェントの本体にも触れない）。

部品・キー・レイヤーの定義は [ui-components.md](ui-components.md) の「寿命と時間（0.26.0）」、作業規約は [AGENTS.md](../AGENTS.md) の「1つの見た目」「時間・空間・情報の寿命」。

## 6. 残っている課題（優先度順）

1. **`ui/board.html` の一枚岩**（300,101 バイト・4,575行）。描画・状態・キー・オーバーレイが1つのスコープにある。寿命（`lifetime.*`）のように、部品ごとのファイルへ分ける作業を続ける。
2. **オーバーレイの余白の調整とショートカットマップ**。左右の余白の比率・キーの案内の位置まで動かせるのは過剰。案内は背景が明るいと読みにくい。既定位置に固定し、地を敷く案を推奨。
3. **休眠したカードの後始末**。いまは畳むだけ。Codex のアーカイブ（`thread/archive`）をまとめて行う操作は、取り消しの導線を用意してから検討する。
4. **初回の一覧（ローカル）**。負荷が高いと `claude.list` が 1.4 秒かかる。差分読み込みの効果を `npm run bench -- --compare` で追う。
5. **Claude デスクトップの入口**。ホスト側に常設の入口が出たら対応する。
