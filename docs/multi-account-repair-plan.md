# マルチアカウント修正計画と検証

対象は0.24.5の監査で再現した8種類・9ケースと、Desktop起動中のCLI選択保存。0.24.6として修正・検証・配布する。

| 修正 | 実装 | 完了条件 |
|---|---|---|
| MA-01 会話コピーの選択 | 本文の最新時刻、次にファイル更新時刻で順位付け | Desktop共通時刻が新しくても最新履歴・cwdを選ぶ |
| MA-02/10 接続設定ID | 管理UUID（設定/既存マーカー）とパス由来ID、一意な旧IDの互換解決 | 移動・列挙順・同名設定の増減で実行先が変わらない。曖昧な旧IDは拒否 |
| MA-03 Codex保存先移動 | 旧パスからの互換リンク、DB保存失敗時の復元 | Vendor DBを書き換えず旧絶対パスで履歴を読める。複数回移動も保持 |
| MA-09 組織照合 | 選択homeの公開identityで照合 | 同じaccountの別組織を誤って拒否しない |
| MA-06 Codex認証隔離 | CLI再開・headless・login・usageで共通の認証環境除去 | 選択homeに別accountのAPI認証を継承しない |
| MA-07 Desktopロック | PID・世代・heartbeatによる保護と放棄lock回収 | 古い空lock・死んだownerを回収、生きたownerを保持。同時回復は1owner |
| MA-08 CLI/ Desktop | CLI保存を独立しDesktop適用待ちを返す | 起動中も選択を保存。同一の起動中プロフィールを開いたファイルのinode/deviceと全main processで確認できた場合は再開 |
| MA-05 使用量 | accountごとの最新sampleと組織IDを保持 | 列挙順によって古い別組織のsampleが勝たない |
| MA-04 不明件数 | ローカルsessionのみ数える | 絞り込み対象と件数が一致 |

選択の保存先、アカウントの集合、会話IDは既存契約を維持する。UIは既存の実行アカウントピッカーと再開欄を直接修正し、CLI保存済みとDesktop適用待ちを表示する。入口・キー・レイヤー・権限を追加しない。会話本文・思考署名・認証トークンを書き換えない。

検証は一時フォルダーとfake CLIを使い、実アカウントの変更やモデルturnを発生させない。回帰テストは監査ケースに加えて旧IDの移行、保存先の複数回移動と失敗復元、Desktop起動中の保存、symlink変更後の実読み込み先、競合ロックを確認する。全npm testと1280×800・5レイアウト×ライト/ダークの画面を確認する。

通常mainに反映後、`npm run update:local`と`npm run pack:mcpb`でGit管理ファイルから配布物を生成する。Chrome登録先の版・内容・拡張ID・Native Messaging保存先を読み戻す。Desktop拡張は正式MCPBで更新し、進行中のチャットを強制終了せず、管理cacheを手編集しない。

Codex・リモート・新規sessionの新しいaccount選択、残量による自動切替は本修正の対象外。正規の実アプリ更新操作が使えない場合は、配布物の検証と実アプリの反映を区別して報告する。

## 検証済みの結果

- `npm test`: 358件成功、失敗0件。
- `tests/claude-handoff.browser.mjs`: 1280×800、5レイアウト×ライト/ダーク、30枚のスクリーンショット。4アカウントと7接続設定の集約、選択保存、CLI再開、指示送信、キーボード、入力途中の文章保持を確認。ブラウザーエラー0件。
- pickerと接続設定の全レイアウトを目視し、行の重なり・画面外へのはみ出しがないことを確認。
- 実環境では4アカウント、Claude7接続設定、保存済み選択1件を確認。管理マーカーのUUIDを引き継ぎ、保存済み選択の参照切れ0件。
- 起動中のDesktopがppbプロフィールのファイルを開いていることをinode/deviceとmain processで確認。実モデルturnは発生させていない。

ローカル配布と実アプリの反映結果は作業ログに保存し、配布物だけの確認を実アプリ完了と扱わない。
