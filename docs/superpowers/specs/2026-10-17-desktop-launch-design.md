# Desktop のリモート起動・Claude アカウント切替・画像添付

日付: 2026-10-17（JST）。状態: **方式のレビュー用。実装・実データの移行は未実施。**

## 目的と合意した範囲

Canban の「今すぐ始める」から、同じ SSH 接続先の作業を Claude と Codex の Desktop で開く。Claude は、Canban で選んだアカウントに切り替えて開く。添付画像は、アプリの入力欄でも画像として確認できる形で渡す。

ユーザーが求める「ログインは1つ」は、**Desktop で同時に操作するアカウントを1つにする**という意味である。各アカウントの認証セッションは保持したまま、登録したアカウント間を切り替える。切替のたびにほかのアカウントをログアウトさせない。複数 Desktop の同時起動は作らない。CLI のアカウントと Desktop のアカウントは別に検証する。

新しいページやナビゲーションは作らない。既存の作成ダイアログ、アカウント管理、共通入力欄、開始結果を使う。依頼は Desktop の下書きとして渡し、送信はユーザーがアプリで行う。接続先の準備と、モデルによる実行開始を区別する。

### 最優先の目標: ログイン状態と会話を保持して切り替える

各アカウントの「セッション」を次の3つに分け、別々に確認する。

| 保持するもの | CLI | Desktop |
| --- | --- | --- |
| 認証セッション | アカウントごとの既存のログイン・更新経路と Keychain の参照を維持する | アカウントごとのログイン状態と、その状態を復号・更新する既存の OS 保存先を維持する |
| 会話と作業の文脈 | 元の会話 ID、履歴、作業フォルダー、再開先、キューのアカウントを維持する | 元の会話 ID、履歴、作業フォルダー、保存済みの下書きを維持する |
| 実行中の処理 | Desktop の切替で停止・再起動せず、開始時のアカウントのまま継続する | 再起動を伴う方式では実行プロセスの連続動作を保証しない。処理中の切替を待機させ、保存と再開を確認する |

正常な認証が残る通常切替では、**ログアウト0回・再ログイン0回**を受け入れ条件とする。初回は CLI と Desktop にそれぞれ必要なログインを行い、以後は保持済みの認証を使う。ログインが必要なのは、初回登録、ユーザー自身のログアウト、認証の失効・取消しなど、再認証が必要と確認できた場合に限る。

CLI だけでアカウントを選ぶ操作は Desktop のアカウントを切り替えない。Desktop の切替は既存 CLI の設定フォルダーを rename せず、標準の CLI 保存先やグローバルな環境変数も別アカウントへ向け直さない。既に実行中の CLI と追加依頼のキューは、開始・登録時のアカウントと保存先を保つ。

期限切れ access token の通常更新は、ユーザーにログインし直してもらう操作とは分ける。CLI の更新は既存のアカウント別ロックと保存処理、Desktop の更新はアプリ自身の認証処理に任せる。通信断・タイムアウト・429・サーバー障害・状態確認の失敗だけではログイン情報を消さず、「状態を確認できません」として再確認できるようにする。CLI と Desktop のトークンを相互コピーして解決しない。

## 1. 共通の起動処理

起動要求は `agent`、実行先の `hostId/cwd`、選択した Desktop アカウント、本文、画像 ID、既存の `clientRequestId` を持つ。Desktop のログインはこの Mac 上で選び、SSH の作業先とは別の値として扱う。リモート作業だからという理由で、この Mac の Desktop アカウント選択を拒否しない。

起動の順序を「入力と接続先の検証 → アカウントの準備 → 必要な空 thread の作成 → アプリを開く → 画像を貼り付ける案内」とする。事前検証の失敗では外部操作をしない。アカウントの終了待ち・初回ログイン待ちは正常な保留状態として返し、現在の `launchOnce()` の結果不明とは分ける。

開始記録には `prepared`・`waiting-for-quit`・`waiting-for-login`・`opening`・`opened`・`uncertain`・`failed` を保存する。各外部操作の前後と、作成済み thread ID を記録する。同じ要求の再開では同じ thread を使う。副作用が発生したか不明な場合は自動再実行しない。

本文と画像 ID は既存の Canban 保存先に置く。記録へトークン・cookie・CLI の認証内容を追加しない。アプリを開く前には要求のアカウントと接続先を再検証する。

### SSH の一致判定

Codex 登録済み接続と Claude の環境の対応は、alias 文字列だけで決めない。ローカルの SSH 設定を実行せずに解決した host・user・port と、双方のアプリの接続定義を照合する。`ProxyCommand` などの任意コマンドを一致判定のために起動しない。解決できない接続や候補が複数ある場合は、同じ接続とは扱わず選び直しを案内する。

### Claude

選択した Desktop プロフィール内の環境と SSH 定義を読み直す。アカウントが変わった場合、別アカウントで保存された環境 ID をそのまま使わない。明示された接続先と作業フォルダーを検証して、新規の SSH URL を生成する。Desktop の画像はこの Mac の画像を使い、Canban が先にリモートへ転送しない。

### Codex

SSH の新規画面用 URL を捏造しない。対象接続先の公式 `codex app-server` に、ユーザーの既存設定を使って空 thread の作成・永続化を依頼する。モデルのターンは開始しない。対象 host の履歴から ID と cwd を読み戻し、作成用プロセスが writer を解放した後で、`codex://threads/<id>?hostId=<登録済みhostId>&prompt=<本文>` を開く。

空 thread が現在の公式 API で永続化でき、Desktop がその接続先で開いて本文を下書きに表示することを、実装の最初に隔離データで検証する。成立しなければこの経路を有効にしない。CLI で依頼を実行してから Desktop に見せる方式へ暗黙に変更しない。

現在の Desktop アカウントと一致しない Codex アカウントの自動切替は今回追加しない。Codex の作業先をリモートにする機能と、Claude の別アカウント切替を分けて扱う。

## 2. Claude の Desktop アカウント切替

### 保存先

- 有効な保存先: `~/Library/Application Support/Claude/`。標準アプリが使う実ディレクトリを常にここに置く。
- 未使用プロフィール: `<Canban保存先>/desktop-accounts/claude/profiles/<profileId>/`。有効なプロフィールの保存先はここに重複して置かない。
- 対応表と操作台帳: `<Canban保存先>/desktop-accounts/claude/registry.json` と `switch.json`。権限はファイル600・ディレクトリ700。
- 保存する対応表はプロフィール ID、アカウント ID、active/parked、実体パスだけとする。既存 Desktop の認証をそのまま保存先ごと保持し、CLI のトークンを Desktop へコピーしない。

通常保存先を symlink にしない。アカウント同士の履歴を共有リンクにしない。停止中のディレクトリの rename で入れ替える。同一ファイルシステム上でのみ対応し、別ボリュームでは事前に拒否する。変更前に復元可能なバックアップと目録を用意する。既存の退避フォルダーや過去のバックアップを勝手に再登録・削除しない。

保存先の保持だけでは認証維持の証明にならない。Keychain・暗号化 cookie・アプリのアカウント別 OAuth キャッシュが、切替後も元のアカウントで解決できることを確認する。Canban はログアウト・認証取消し・全アカウントのキャッシュ消去を呼ばず、共有の Keychain 項目を別アカウントの内容で上書きしない。この条件を満たせないプロフィール方式は有効にせず、毎回の再ログインを正常動作として扱わない。

Desktop に内蔵された CLI が、ほかのアカウントの通常 CLI 認証や保存先を上書きしないことも確認する。`CLAUDE_CONFIG_DIR` の指定は設定・履歴の参照先であり、Desktop 自身のログインを切り替える方法として使わない。Desktop を通常の Dock 起動で開き直した場合も含めて確認し、Canban からの起動時だけ成立する状態を認証維持の完了にしない。

### 初回登録

現在のプロフィールは、実ディレクトリ・所有者・現在のアカウントを確認して登録する。別アカウントは「Desktop を接続」から追加する。ユーザーが Desktop を終了した後、現在のプロフィールを退避し、新しい空の標準保存先で Desktop を開く。ユーザーが Desktop 自身でログインする。

CLI アカウントを指定して登録した場合、Desktop で確認できたアカウント ID が一致したときだけ関連付ける。別アカウントでログインしても自動で紐付けを変えない。キャンセルした登録先は保持し、既存プロフィールを戻す操作を用意する。認証画面の自動入力や cookie の書換えは行わない。

### 切替の順序

1. Canban 全クライアント共通の切替ロックを取得し、要求と現在のプロフィールを検証する。同じアカウントとプロフィールなら、読み込んだ実体を確認した既存 Desktop をそのまま使い、終了・再起動・ログインと後続の入替えを行わない。アプリを開くまでロックで保護し、ほかの Canban による切替と競合させない。
2. 起動中の Desktop が別アカウントなら、起動前から「A → B に切り替えて開く」と示す。処理中・入力待ち・状態未確認なら `waiting-for-quit` として待ち、保存と終了を促す。全処理が停止済みで未保存入力を保てると確認でき、ユーザーがこの切替操作を選んだ場合に限り、通常終了をアプリへ依頼して再起動をまとめて扱う。強制終了しない。待機はキャンセルできる。
3. 親・補助プロセスの終了を確認し、既存の統合サイドバーのゲストを書き戻す。台帳が残る、復元に失敗する、別の Canban が操作中の場合は入替えない。
4. 変更前のプロフィールと切替先を目録に記録する。現在の標準ディレクトリを現在の profileId の退避先へ rename し、切替先を標準ディレクトリへ rename する。
5. 標準パスの実体とアカウント ID を再検証し、対応表を更新する。アプリを開き、読み込んだ実体の確認と認証の確認を分けて扱う。
6. プロフィールの起動だけでは「ログイン成功」「依頼開始」と表示しない。ログインが必要な場合は `waiting-for-login` にし、対象アカウントを確認してから依頼画面へ進む。

台帳には各ディレクトリの実パス・device/inode・変更前後の段階を記録する。各 rename の直前にも Desktop の停止と実体を再確認し、既存の標準パスや退避先を上書きしない。入替え中に外部から Desktop が起動したり標準パスを作り直したりした場合は、それ以上動かさず、再び終了するまで待つ。外部が作ったフォルダーを自動削除しない。

プロセスが途中で終了した場合は次回起動で台帳と各実体を照合する。アプリが停止した状態で元に戻すか、完了済みの切替を確定する。状況が曖昧なら書き換えず停止する。Desktop を起動できる状態を復元するまで、次の切替を認めない。

### 履歴・既存機能との共存

Canban は active と parked の全登録プロフィールの履歴を読み取る。同じ実体を一度だけ読み、元のカード ID と所有アカウントを維持する。プロフィールを置いた場所だけで別アカウントと推測しない。セッションの元パスは切替のたびに再解決し、退避前のパスを保持した書込みを拒否する。

統合サイドバーのゲストは切替前に解消し、次のアカウントへ持ち越さない。ゲストを別アカウントに表示する機能と、そのアカウントとして実行する機能を区別する。同じ Desktop ID が複数プロフィールにある場合は、所有アカウントと CLI ID で照合し、曖昧な記録を自動統合しない。

## 3. 画像を Desktop の入力欄へ渡す

現行アプリの新規 URL には、Code の画像を直接添付する確認済み経路がない。本文へパスを書くだけで「画像を添付しました」と表示する現状をやめる。

最初の対応は、開始結果に **「画像をコピー」** を表示し、ユーザーがアプリの入力欄で `⌘V` を押して画像として添付する方式とする。この1回の貼り付けが必要な点は、開始前から案内する。**自動でサムネイルを入れる機能は、この方式だけでは実現しない。**

コピーは macOS の通常のファイルクリップボード形式で、検証済みのローカル画像だけを渡す。起動時に無断でクリップボードを上書きしない。任意のパスは受け付けず、Canban の画像 ID・形式・件数・サイズ・ハッシュを検証する。貼り付け後のリモート転送は Desktop の標準の画像添付処理が受け持つ。

この方式を有効にする前に、Claude Code と Codex の入力欄が、画像1枚・複数枚のファイル貼り付けを画像として扱うことを実機で確認する。対応しないアプリにはコピー成功を添付成功として返さず、「アプリの添付から選択」の案内と画像一覧を表示する。

自動添付まで必要な場合は、アプリの正式な画像受取 API が利用できるか、明示した OS アクセシビリティ連携が必要になる。現在は経路を確認できていないため、この設計の完了条件に混ぜない。本文・画像を勝手に送信する UI 自動操作は行わない。

Canban 内では共通入力欄の既存サムネイルを維持する。画像を再編集するときも画像 ID からプレビューを読み戻し、空のサムネイルにしない。

## UI・キー・状態の伝え方

- 作成ダイアログはレイヤー3のまま。待機・切替・画像コピーは同じ開始結果に置く。別の確認ページやフローティング操作を追加しない。
- アカウントの初回接続は既存のアカウント管理パネルに置く。タスク開始の選択肢には「Desktop 接続済み」「初回ログインが必要」を示す。
- 起動中の Desktop が別アカウントなら、「終了待ち → 切替 → 選択プロフィールで起動」を表示する。実際の処理段階を混同しない。
- 接続済みアカウントには「再ログインせず切替」を示す。再認証が必要な場合は CLI / Desktop のどちらかと、そのアカウントを示す。片方の認証失効で両方をログインし直す案内を出さない。
- 同じアカウントなら現在のアプリをそのまま開く。別アカウントでも停止済みなら1回の「切り替えて開く」で進む。通常終了が必要な場合も最初から切替先を示し、毎回のアカウント設定画面や確認ダイアログの往復を求めない。
- 実行中の仕事を中断する切替は行わない。待機中も会話・依頼文・添付画像を保持し、明示した停止待ち条件を満たしたら同じ要求を続ける。状態未確認の処理は完了したと推測しない。
- `⌘/Ctrl+Enter` は開始要求、`Esc` は最上位のダイアログを閉じる。閉じるだけでは切替待機を取り消さず、待機を中止する操作を明示する。下書きと画像を保つ。
- 新しいボタンは `Tab` と `Enter` で操作でき、⌘K に「Desktop の切替を取り消す」「添付画像をコピー」を追加する。キーの案内は既存部品で表示する。新たな全画面ショートカットは作らない。
- 「画像をコピー」はクリップボードへの保存、「アプリで画像を貼り付け」は次のユーザー操作として表示し、コピーを添付完了と扱わない。

## 実装の区切りと受け入れ条件

1. **実現性の確認**: 隔離した空の Codex thread を作って解放し、登録済み SSH の Desktop で本文を下書き表示できること。両アプリで画像のファイル貼り付けが画像になること。モデルへ依頼を送らない。成立しない経路は後続実装へ進めない。
2. **Claude の切替**: 偽のプロフィールで初回登録・切替・中断復旧・同時要求・外部切替・失効ログイン・ゲスト復元失敗を検証する。切替前後の履歴の件数と内容、CLI アカウント、旧バックアップを保つ。正常な認証を持つ A/B で `A → B → A` を3往復し、再ログイン0回・ログアウト0回、各 CLI/Desktop の会話 ID と再開先の保持を実機で確認する。通常の Dock 起動、CLI の継続動作、アプリ再起動後も確認する。実プロフィールの移行は、計画表示とバックアップを確認した後に行う。
3. **Desktop 起動**: Claude のローカル/SSH、Codex のローカル/SSH、同名 alias の異なる user/port、存在しない接続先、別アカウントの環境 ID を検証する。再送・アプリ起動失敗・応答切断で、空 thread や開始要求が重複しない。
4. **画像と UI**: 画像1枚/複数枚、ダイアログの開き直し、アカウント切替待ち、キャンセルを検証する。本文に不要な画像パス列を追加せず、コピー後に実際の Desktop のサムネイルを確認する。
5. **リリース検証**: 実装ごとにバージョンを同期し、日本語でコミットする。`npm test`、`node --test tests/board-smoke.browser.mjs`、1280×800のライト/ダークのボード/時間軸を確認する。ローカル/CI と、実際のアプリでの確認結果を分けて報告する。

再認証が必要なケースでは対象の CLI/Desktop だけを回復させ、もう片方と他アカウントを保つ。通信断と認証失効を区別し、同じアカウントを再選択したときに再起動せず、処理中の切替で実行を失わないことも受け入れ条件に含める。認証情報は正規の更新で変わり得るため、維持の確認をトークン値やファイル全体の単純なバイト一致だけで判定しない。
