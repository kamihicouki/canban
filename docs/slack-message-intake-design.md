# Slackメッセージの取り込み設計

状態: 設計インタビュー中。機能の実装・Slackへの接続は未着手。
最終更新: 2026-10-06

## 確定した要件

- Slackの依頼を拾って対応漏れを防ぎ、会話を材料として仕事を整理し、エージェントに渡せるようにする。
- ボード内にSlackタイムライン専用リストを置く。
- 特定のメッセージ1件を起点に新しいカードを作る。2件目以降はあとから追加できる。
- 既存カードにもSlackメッセージを紐づけられる。
- チャンネルやDMは、任意の既存カテゴリに対応付ける。複数の会話を同じカテゴリにまとめられる。
- 対応先のカテゴリがなければ追加できる。未分類も許可する。

## 次に決めること

- 専用リストとチャンネル・DMの対応、および複数の会話を同時に表示する方法。
- 接続するワークスペースと、公開・非公開チャンネル、DM、グループDMの対象範囲。
- 作成するカードの種類、取り込み先リスト、紐づけ可能な既存カードの種類。
- メッセージとスレッドの閲覧、取り込み済み表示、同じメッセージの複数カードへの紐づけ。
- Slack側の編集・削除とカード側の記録の関係。
- Slackへの返信・リアクション・既読反映を扱うか。
- 認証、取得・更新、保存、添付ファイル、エージェントへ渡す内容と実行開始の扱い。
- レイヤー、キー、5レイアウトの操作経路、検証と導入の条件。

## 既存モデルとの接点

- カテゴリとカードの配置先リストは別の軸。現在、カードのカテゴリは1つで、未分類もある。
- 現在のタスクカードはタイトル・説明・カテゴリ・ラベル・リストを持つ。Slackの元メッセージを識別する専用属性はない。
- 既存のカードのセッション紐づけと、Slackメッセージの参照は意味が異なる。
- 2026-10-06のコード調査ではSlack連携は見つからなかった。
- ボード以外のページは増やさず、接続などの管理は既存の管理パネルの契約に従う。
